# U5 NPC 대화·언어 — Business Rules

번호는 `BR-U5-n`. 근거 열의 Q는 FD-U5 답, A5는 플랜 가정. 설계 이탈은 domain-entities §7 / business-logic-model §9.

## 1. 대화의 수명
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U5-1 | 대화는 (세션, NPC)당 하나다(`conversations`의 `UNIQUE (session_id, npc_id)`). 같은 NPC를 다시 찾으면 그 대화가 이어지고 이전 메시지를 모두 읽을 수 있다 | A5-1, US-4.1 |
| BR-U5-2 | `start`는 대화를 만들거나 가져오기만 한다(LLM 없음). NPC 소개는 캐노니컬 `name`·`role`·`description`이다 | 이탈 3, US-4.1 |
| BR-U5-3 | `say`는 플레이어 발화와 NPC 답을 **한 트랜잭션**으로 남긴다. 반쪽 대화는 남지 않는다 | BR-U4-14 |
| BR-U5-4 | `history`는 읽기다. 닫힌 세션에서도 읽을 수 있고 LLM이 필요 없다. 없으면 404 | A5-3 |
| BR-U5-5 | 대화는 턴을 소모하지 않는다. 턴은 `EndTalk`(U4, 1턴)로만 흐른다. 대화 호출 수에는 상한을 두지 않는다(플레이어의 속도가 상한이다) | A5-2, FR-C4 |
| BR-U5-6 | `EndTalk`는 `NPC_TALKED` 타임라인 한 줄을 남긴다(`npc_id`, `npc_name`, `region_id`, `region_name`, `messages`). 대화 없이 끝내도 유효하다(`messages: 0`) | FR-C4, U4 연결 |

## 2. 아는 범위 (핵심)
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U5-7 | NPC의 컨텍스트에 들어갈 수 있는 것은 **그 NPC가 사는 지역에서 닿는 것**뿐이다: 정적 지식(direct + inherited + global), 그 지역의 전언(hearsay), 그 지역의 활성 세션 소문, 그리고 NPC 자신의 설명. 그 밖의 지식·소문 id는 프롬프트에 없다 | FR-F4, US-4.2, 이탈 1 |
| BR-U5-8 | `build_context`는 순수 함수다. I/O가 없고, 같은 입력은 같은 컨텍스트를 낸다(정렬 키에 id를 넣어 동률에서도 결정적) | FR-F4, US-4.2 넷째 |
| BR-U5-9 | 한도: facts 12 · hearsay 6 · rumors 8 · 최근 메시지 10. 잘릴 때 남기는 순서는 facts = direct → inherited → global(같으면 확신도 높은 순), hearsay = 경로 감쇠 적은 순, rumors = 승격 → 지지도 높은 순, 메시지 = 최신 순 | Q3=A |
| BR-U5-10 | 컨텍스트 밖을 물으면 모른다고 하거나 소문대로 말하고, 지어내지 않는다(시스템 프롬프트 가드 + 예제 테스트) | US-4.2 셋째 |
| BR-U5-11 | 컨텍스트에는 소문의 **왜곡된 문장 그대로**가 들어간다. 그 소문의 원본 캐노니컬 문장은 넣지 않는다 | US-4.3 첫째 |

## 3. 소문을 전하는 말투
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U5-12 | 승격된 소문(`promoted`)은 `known`으로 표시해 사실처럼 확신해서 말한다 | US-4.3 셋째 |
| BR-U5-13 | 왜곡도 ≥ 0.5인 소문은 `uncertain rumor`로 표시해 "들었다", "확실하진 않지만" 같은 전언 표현을 붙인다. 그 사이는 `rumor`로 중립적으로 전한다 | US-4.3 둘째, A5-4 |
| BR-U5-14 | 전언(hearsay)은 `HEARD (uncertain)` 묶음으로 들어가고 같은 불확실한 말투를 쓴다 | 이탈 1, US-4.3 |

## 4. 언어
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U5-15 | 표시 언어는 서버 기본값(`TRANSLATION_TARGET_LANG`, 기본 `ko`)이고, 요청의 `?lang=`이 그것을 덮어쓴다. 지원 집합(`SUPPORTED_LANGS`, 기본 `ko,en`) 밖은 400 | Q1=A |
| BR-U5-16 | NPC 답은 표시 언어로 **직접 생성**한다. 대화 한 번 = LLM 호출 1회이고 번역 경로를 거치지 않는다 | A-1, FR-G3, US-4.1 셋째 |
| BR-U5-17 | 컨텍스트의 지식·소문은 영어 원문으로 넣고 NPC가 표시 언어로 옮겨 말한다 | FR-G3, US-9.2 둘째 |
| BR-U5-18 | 대화문은 임베딩하지 않고 번역 캐시에도 넣지 않는다. `Message.lang`이 그 메시지가 무엇으로 쓰였는지 남긴다 | FR-G2, A5-5 |
| BR-U5-19 | `lang`이 원문 언어(영어)와 같으면 번역을 요청하지 않고 `*_ko` 필드는 `None`으로 둔다 | Q1=A |
| BR-U5-20 | 임베딩·검색 대상 텍스트(지식·엔티티·WikiPrior·소문)는 계속 영어로 생성·저장한다 | FR-G2, C-1, US-9.1 첫째 |
| BR-U5-21 | 모든 UI 라벨은 i18n 사전에서 온다. `ko`와 `en` 사전이 있고, 표시 언어를 바꾸면 데이터 표시와 라벨이 함께 바뀐다 | Q2=A, FR-G5, US-9.4 |

## 5. 번역 정리와 경계
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U5-22 | `TranslationStore.purge`는 필터(`kind`/`ids`/`world_id`/`session_id`) 하나 이상을 요구한다. 필터가 없으면 `ValueError`(전체 삭제 방지) | Q4=A, 이탈 4 |
| BR-U5-23 | 정리 호출은 조립 루트(`api/`)에만 있다. 소문 재생성이 지운 id, 월드 교체·import로 사라진 캐노니컬(월드 범위)이 대상이다. localization이 없으면 건너뛰고, 정리 실패는 응답을 깨지 않는다(로그만) | Q4=A, FR-G1 |
| BR-U5-24 | play는 localization을 import하지 않고, localization은 play를 import하지 않는다. 번역은 `api/schemas.py`에서 입힌다 | FR-G1, US-9.3 첫째 |
| BR-U5-25 | 세션이 하나도 없는 월드에서도 번역이 동작한다(에디터·knowledge 응답) | US-9.3 둘째 |
| BR-U5-26 | 같은 항목을 동시에 여러 화면이 요청해도 두 번 번역하지 않는다(이미 구현된 in-flight 억제) | US-9.3 셋째, A5-9 |

## 6. 가드·오류
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U5-27 | 대화는 진행 중 턴 실행이 있어도 허용한다. 대화는 턴 상태(소문·왜곡도·사건·세션 턴)를 쓰지 않으므로 잃을 갱신이 없다 | A5-6, U4 가드 범위 |
| BR-U5-28 | 플레이어가 NPC의 지역에 없으면 400. NPC가 그 월드에 없으면 404. 빈 `text`는 400. 닫힌 세션의 `say`는 409 | services §3.5, A5-6 |
| BR-U5-29 | LLM 제공자가 없으면 `say`만 503이고 `start`·`history`·모든 읽기는 동작한다 | 이탈 3, NFR-4, US-1.4 |
| BR-U5-30 | LLM이 빈 응답을 돌려주면 대화를 끊지 않고 표시 언어의 고정 문구로 답한다. 호출이 예외로 실패하면 메시지를 저장하지 않고 오류를 올린다 | A5-4, NFR-4 |
