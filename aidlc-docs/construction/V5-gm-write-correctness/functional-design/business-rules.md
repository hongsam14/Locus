## 회귀 시나리오 (TP-V5-*)

### 시험 방식 (NFR-10)

- **두 저장소**에서 돈다: 인메모리 저장소와, SQLite 파일 위의 운영용 SQL 어댑터. 역공학이 결함을 재현한 두 환경이다.
  - 인메모리는 작업 단위가 저장소 전체 잠금이라, 겹침이 작업 단위 **밖**의 읽기에서만 난다(지지도 조정, 씨앗 확인, 승인, 몫 읽기).
  - SQL 어댑터는 작업 단위 **안**의 읽기도 겹친다(해소의 지역 왜곡도 읽기). SQLite는 `FOR UPDATE`를 무시하므로 행 잠금 없이 겹침이 드러난다.
- **끼워 넣기**: 저장소를 감싼 시험용 문이 정해진 메서드(예: 첫 요청의 지역 왜곡도 읽기) 직후에 멈춰, 둘째 요청이 같은 자리에 오기를 잠깐(예: 0.5초) 기다린다.
  - 고친 코드에서는 둘째 요청이 짧은 쓰기 잠금에서 기다리므로 그 자리에 오지 못한다. 문은 시간 초과로 열리고 결과는 차례로 한 것과 같다.
  - 고치기 전 코드에서는 두 요청이 모두 읽은 뒤 쓰므로 결함이 드러난다. 시험을 쓸 때 고치기 전 코드에서 한 번 실패하는 것을 확인한다(돌연변이 확인).
- LLM은 가짜다. 일괄 생성 시험은 가짜 LLM이 동시에 몇 번 불렸는지 센다.
- PostgreSQL 실제 잠금은 오프라인으로 돌리지 않는다. 운영자 확인 목록에 남긴다(NFR light에서 절차를 적는다).
