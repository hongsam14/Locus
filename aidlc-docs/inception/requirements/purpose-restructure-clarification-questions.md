## Question R2-1
플레이할 때 **사용자의 역할**은 무엇입니까?

**배경**
- 지금 화면(`SessionPanel`, UI의 약 51%)은 GM 콘솔입니다. 사용자가 이벤트를 만들고, 턴을 넘기고, 루머 지지도와 지역 왜곡도를 직접 조정합니다.
- LLM이 이벤트를 제안하는 기능(`EventSuggester`)은 이미 있지만, 지역 UUID만 보고 제안합니다.
- 이 답에 따라 화면 구성(플레이 화면, GM 화면, 둘 다)이 정해집니다. 플레이어 캐릭터·위치 모델을 새로 만들지, 이벤트를 자동으로 진행할지도 함께 정해집니다.

A) **플레이어.** 시스템(LLM)이 GM 역할을 맡습니다. 턴마다 이벤트를 제안하고 자동으로 적용하며, 소문이 퍼집니다. 사용자는 캐릭터로서 세계를 돌아다닙니다. — GM 콘솔은 플레이 화면으로 바뀝니다. 이벤트 자동 진행(제안 → 자동 승인)과 플레이어 상태 모델을 새로 만듭니다. 지금의 GM 조작 UI는 걷어냅니다.
B) **GM.** 지금처럼 사용자가 GM으로 세계를 굴립니다. — 지금 방향을 유지하고, 개선은 UX와 결함 수준에 그칩니다. "플레이"는 GM 시점에서 세계를 운영하는 일이 됩니다. 새 모델은 필요 없고 범위가 가장 작습니다.
C) **솔로 TRPG: 플레이어 + GM 모드.** 기본은 플레이어 시점이고, 필요하면 GM 모드로 개입합니다(이벤트 주입, 소문 조작, 세계 상태 보기). *(권장)* — 플레이 화면과 GM 화면이 둘 다 필요해서 범위가 가장 큽니다. 대신 이미 만든 GM 도구를 살리면서 목적은 플레이어 시점으로 보여 줄 수 있습니다. **권장 이유**: 포트폴리오에서 "직접 플레이하는 세계"와 "그 세계가 움직이는 원리(왜곡도, 지지도, 전파)"를 둘 다 보여 줄 수 있습니다.
X) Other (please describe after [Answer]: tag below)

- **A와 C의 차이**: A는 GM 조작을 사용자에게서 빼고, C는 모드로 남깁니다.

[Answer]: C — 플레이어 + GM 모드 (대화창 답변, 2026-09-29)

## Question R2-2
플레이에서 **NPC와 어떻게 만납니까?**

**배경**
- Locus의 처음 목적은 "지역 X에 사는 NPC가 아는 것"을 만드는 것이었습니다.
- 지금 그 결과(정적 지식 + 세션 루머)는 목록으로만 볼 수 있습니다(`RegionPanel`). NPC라는 존재나 대화는 코드에 없습니다.
- 이 답에 따라 NPC 모델을 새로 만들지, 대화용 LLM 경로를 둘지, 처음 목적을 플레이 안에 어떻게 되살릴지가 정해집니다.

A) **LLM NPC와 대화한다.** NPC는 자기 지역에서 알 수 있는 것(정적 지식 + 들은 소문, 왜곡 포함)만 압니다. 모르는 것은 모른다고 하거나 소문대로 틀리게 말합니다. *(권장)* — 새로 만들 것: NPC 모델(지역 거주, 이름, 역할), 대화 엔드포인트, "아는 범위" 가드 프롬프트. 처음 목적인 공간 지식이 플레이 메커니즘이 됩니다. 대화할 때마다 LLM 호출이 생깁니다. **권장 이유**: "지역마다 NPC가 다르게 안다"를 데모에서 가장 직접 보여 줄 수 있습니다.
B) **대화 없이 지역 지식을 열람한다.** 플레이어가 지역에 가면, 그곳에서 들을 수 있는 이야기와 소문 목록을 봅니다. — 새 LLM 경로가 없어 단순합니다. 대신 플레이 감각은 약하고, 지금 목록 화면의 연장에 그칩니다.
C) **NPC 상호작용은 범위 밖.** 외부 NPC 런타임의 몫으로 남기고 API만 둡니다. — 데모에서 NPC를 보여 줄 수 없습니다. 이번 범위는 세계 시뮬레이션에 한정됩니다.
X) Other (please describe after [Answer]: tag below)

[Answer]: A — LLM NPC와 대화 (대화창 답변, 2026-09-29)

## Question R2-3
플레이어는 **지도 위에 존재하고 이동합니까?** (R2-1이 A 또는 C일 때만 해당)

**배경**
- 토폴로지(지역 계층 + 가중치 있는 연결)는 지금 지도 오버레이로 보이기만 합니다.
- 지역을 클릭하면 어디든 볼 수 있고, 턴은 GM이 버튼으로 넘깁니다.
- 이 답에 따라 토폴로지가 "게임 지도"가 되는지(이동 규칙, 이동 비용), 무엇이 시간(턴)을 흐르게 하는지가 정해집니다.

A) **위치가 있고, 연결된 지역으로만 이동한다. 이동과 행동이 턴을 진행한다.** 연결 가중치는 이동 비용이 되고, 막힌 길은 못 지나가거나 비용이 큽니다. *(권장)* — 플레이어 상태(위치, 턴)를 새로 만들고, 이동 규칙을 둡니다. 토폴로지와 소문 전파가 같은 지도 위에서 보이게 됩니다. **권장 이유**: 공간이 플레이에 실제로 의미를 갖습니다. 멀리 있는 소문일수록 왜곡되어 들린다는 핵심 개념이 체감됩니다.
B) **위치는 있지만 이동은 자유이고, 턴은 버튼으로 넘긴다.** — 구현은 단순합니다. 공간은 "현재 보고 있는 지역" 정도의 의미만 가집니다.
C) **위치 없이 아무 지역이나 본다.** 지금과 같습니다. — 새 모델이 없습니다. 대신 플레이어가 세계 안에 있다는 감각이 없습니다.
X) Other (please describe after [Answer]: tag below)

[Answer]: A — 연결 따라 이동, 행동이 턴 진행 (대화창 답변, 2026-09-29)

## Question R2-4
사용자는 **월드를 어떻게 구성합니까?**

**배경**
- 지금 UI로 할 수 있는 빌드는 하드코딩된 데모(`with_map=false`)뿐입니다.
- API로도 이미지를 JSON에 실어 보낼 수 없습니다(A7).
- 메모와 지도가 같은 지역을 말하면 연결이 사라지고(A1), 같은 월드를 다시 빌드하면 노드가 두 벌이 됩니다(A3).
- 토폴로지 편집 수단이 없습니다.
- 데모 월드(Aldermoor)는 지역이 몇 개뿐입니다.
- 이 답에 따라 입력 UI, 월드 편집 UI, 데모 월드 규모, 수집 파이프라인 결함 수정 범위가 정해집니다.

A) **자료를 올려 자동 구성하고 UI에서 보정한다.** 메모 텍스트, 구조화 지도 JSON, 지도 이미지를 올리면 LLM 파이프라인이 월드를 만들고, 사용자는 지역·연결·지식을 고칩니다. — 새로 만들 것: 입력 UI, 토폴로지 편집. 고칠 것: 이미지 전송, 병합 결함, 재빌드 중복.
B) **데모·템플릿 월드를 고르고 간단히 편집한다.** — 데모는 쉽게 돕니다. 대신 "월드를 구성한다"는 경험은 약하고, LLM 수집 파이프라인은 거의 쓰이지 않습니다.
C) **UI에서 직접 그린다.** 지역을 추가하고 연결을 긋고 지식을 입력하는 수동 에디터입니다. — LLM 수집 파이프라인은 보조가 되거나 빠집니다. 결과가 결정적이지만 입력 수고가 큽니다.
D) **A + 원클릭 데모 월드.** A에 더해, TRPG에 맞게 키운 데모 월드를 한 번에 불러옵니다(지역 10~15개, NPC, 사건 씨앗). *(권장)* — A의 작업에 더해 데모 월드 콘텐츠를 만듭니다. **권장 이유**: 보는 사람은 바로 플레이할 수 있고, 자기 자료로 월드를 구성하는 흐름도 보여 줄 수 있습니다.
X) Other (please describe after [Answer]: tag below)

[Answer]: A + C (+ D의 원클릭 데모 월드) — "(1)+(4). 사실상 월드 에디터임. 그리고 그렇게 만든 월드를 저장하고 로드할 수도 있어야 함. (이미 저장포멧이 있긴 함)" (대화창 답변, 2026-09-29. 대화창 선택지 (1)=자료 업로드 + 원클릭 데모, (4)=UI에서 직접 그리기)

## Question R2-5
플레이에 쓰이지 않는 **캐노니컬 부가 기능**을 어떻게 하시겠습니까?

## Question R2-6
게임 콘텐츠의 **언어**는 어떻게 하시겠습니까?

**배경**
- 지금은 LLM이 콘텐츠(루머, 이벤트, 지식)를 영어로 만들고, 번역 캐시(`locus/translation`, PostgreSQL `translations`)가 읽을 때 백그라운드에서 한국어로 번역합니다. 화면에는 원문 토글이 있습니다. 직전 사이클에서 고르신 방식입니다.
- 번역 모듈은 세션 저장소에 묶여 있고, 캐노니컬 질의는 번역하지 않습니다.
- 이 답에 따라 번역 모듈을 남길지, LLM 호출 수를 어떻게 할지, 화면 언어를 무엇으로 할지가 정해집니다.

A) **콘텐츠를 처음부터 설정한 언어(기본 한국어)로 만든다. 번역 캐시는 없앤다.** — 프롬프트에 출력 언어를 지정합니다. 번역 모듈, `translations` 테이블, `*_ko` 필드, 원문 토글이 사라집니다. LLM 호출이 줄고 구조가 단순해집니다. 직전 사이클의 원문 토글 기능은 잃습니다. 입력 자료가 영어면 생성 콘텐츠만 한국어가 됩니다.
B) **지금처럼 영어로 만들고 한국어 번역 캐시를 둔다.** — 번역을 유지하되, 세션 도메인에서 떼어 독립 모듈로 옮깁니다. 원문 토글이 남습니다.
C) **영어로만 한다.** — 번역을 없애고 UI도 영어로 둡니다. 해외 포트폴리오라면 맞습니다. 한국어 폰트(Gaegu)와 i18n은 정리 대상이 됩니다.
X) Other (please describe after [Answer]: tag below)

- **권장 없음**: 포트폴리오를 누구에게 보여 주실지(국내·해외)에 따라 달라집니다. 국내라면 A가 가장 단순합니다. 원문 토글을 살리고 싶으시면 B가 맞습니다.

[Answer]: B — "(2). 영어를 쓴 이유는 벡터라이즈 때문임." (대화창 답변, 2026-09-29) → 임베딩 대상 텍스트는 영어로 생성하고, 표시는 한국어 번역 캐시로 한다. 번역 모듈은 세션 도메인에서 분리한다.

- 다만 Q3 = A(경계 재정리)라서 패키지를 다시 나누게 됩니다. 이 기능들이 새 구조에서 어디에 놓일지, 이번에 손볼지는 정해야 합니다.

A) **지우지 않고 월드 구성 쪽 경계 안으로 옮겨 두기만 한다. 완성과 수정은 다음 사이클에 한다.** *(권장)* — 코드와 테스트가 남고, 빌드 흐름에서도 지금처럼 돕니다(빌드 LLM 비용 유지). 문서에는 "진행 중 기능"으로 표시합니다. 이번 범위는 커지지 않습니다. **권장 이유**: 이번 범위에 이미 월드 에디터, 플레이 루프, NPC 대화, 경계 재정리가 들어와 있습니다.
B) **옮기면서, 월드 에디터에 닿는 것은 이번에 완성한다.** 보강 Q&A를 에디터에 붙이고 고장을 고칩니다. wiki 조회 결과도 에디터에 보입니다. — 에디터가 풍부해집니다. 대신 범위가 늘어 유닛이 하나 이상 더 생깁니다.
C) **이번에는 전혀 건드리지 않는다.** 파일 위치와 코드를 그대로 둡니다. — 경계 재정리에서 이 부분만 예외가 됩니다. 새 구조와 옛 구조가 섞여 남습니다.

## Question R2-8
월드 저장·로드에 쓸 **"이미 있는 저장 포맷"**은 어느 것입니까?

**배경**
- R2-4 답에서 "만든 월드를 저장하고 로드할 수 있어야 하고, 저장 포맷은 이미 있다"고 하셨습니다.
- 코드에는 후보가 셋 있습니다.
  - ① **export JSON**: `locus export`, `GET .../export`. 지역·연결·엔티티·지식·스코프 전체가 들어 있습니다. 불러오기 경로는 없습니다.
  - ② **Locus Map JSON**: `examples/demo_world/map.json`. 지역과 연결만 있는 입력용 포맷입니다.
  - ③ **WorldInputs JSON**: 원자료 묶음(메모, 지도)입니다. `build-world --inputs`에 씁니다.
- 이 답에 따라 저장·로드 포맷, NPC 같은 새 요소를 어디에 담을지, 왕복 테스트(PBT-02) 대상이 정해집니다.

A) **① export JSON을 저장 포맷으로 삼고 불러오기를 추가한다.** 포맷 버전 필드와 NPC 등 새 요소를 더합니다. *(권장)* — 편집 결과가 그대로 저장되고 LLM 없이 바로 로드됩니다. 저장 → 로드 왕복이 PBT 대상이 됩니다. **권장 이유**: 편집한 월드를 잃지 않고 다시 여는 데 필요한 정보를 모두 담는 포맷은 ①뿐입니다.
B) **② Locus Map JSON을 확장해 저장 포맷으로 쓴다.** — 사람이 손으로 쓰기 쉬운 포맷을 유지합니다. 대신 지식, 스코프, NPC까지 담도록 크게 확장해야 합니다.
C) **③ 원자료를 저장하고, 로드할 때 다시 빌드한다.** — 저장은 단순합니다. 대신 LLM 결과가 매번 달라지고, UI에서 편집한 내용이 사라집니다.
X) Other (please describe after [Answer]: tag below)

[Answer]: A — export JSON + 불러오기 추가 (대화창 답변, 2026-09-29)
