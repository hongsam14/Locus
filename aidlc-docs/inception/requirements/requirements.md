## 2. Problem Statement & Vision

**문제(Why)**: 현재 게임 NPC의 지식·대사는 기획자의 수동 스크립트에 의존한다. NPC 수 증가 시 작성·관리 비용이 선형 이상으로 증가하고, NPC가 자신이 살아온 지역의 맥락(지리·문화·소문·관습)을 반영하지 못하며, 컨셉 문서·지도·컨셉아트의 세계관 정보가 구조화되지 않은 채 흩어져 재활용되지 못한다.

**비전(What)**: 비정형 세계관 자료를 모두 입력받아, 게임 지형과 매핑되는 **구조화된 지식 기반을 자동 생성**한다. 산출물은 (1) 지역 간 연결 네트워크 토폴로지, (2) 지역별로 스코프가 지정된 온톨로지/지식 그래프이며, 최종적으로 NPC 대사·행동 생성 시스템(LLM 기반 NPC)의 **컨텍스트 소스**로 제공되어 수동 스크립트를 대체한다.

## 3. Key Domain Concepts

### 3.1 Spatial Knowledge (공간 지식)
한 개체(NPC)가 태어나거나 자라거나 거주하는 환경에서 형성되는 **문화적 환경의 영향을 받은 지역적 컨센서스(local consensus)**.
- 같은 마을의 NPC들은 공유 지식(지명·인물·사건·관습)을 가진다.
- 지리적으로 멀거나 단절된 지역의 NPC는 해당 지식을 모르거나 왜곡된 형태(소문)로만 안다.
- 지식의 전파·컨센서스는 지형의 연결 구조(길·강·산맥·교역로)에 의해 제약된다.

### 3.2 Common-sense Wiki (상식 Wiki) — 신규, 핵심
실세계의 지질·기후·물류 등 **불변 prior(상식)**를 담는 영속적 지식 베이스. (CL1=B, CL3=C)
- **본질**: 실세계 지도·텍스트를 **Locus의 동일한 수집→토폴로지→온톨로지 파이프라인**으로 처리해 만든 **"실세계 디지털 트윈"** 지식 그래프. 가상 세계 그래프와 **동일 포맷**으로 저장된다. (CL2=B + 부연)
- **역할 ①(토폴로지 가중치)**: 지형 제약을 연결 강도/접근성에 반영 (예: A–B 사이 산맥 → 정보·물류 교류 지연 → 연결 약화).
- **역할 ②(고증 생성)**: 입력 자료로부터 추가 지식을 추론·보강 (예: C 지역이 분지 → 실세계 데스밸리 등 참조 → "고온 기후"라는 고증을 자동 생성).

### 3.3 Knowledge Augmentation (지식 보강 Q&A) — 신규, 핵심
상식 Wiki를 근거로, 시스템이 기획자에게 질문을 던져 **대화형으로 지식 그래프를 보강**하는 루프 (AI-DLC식 질의응답). MVP 포함. (CL4=A)
- 보강 질문 생성 근거 (CL5=A,B,C):
  - **A) 그래프의 빈틈/모순** (예: 인접 지역인데 공유 지식 없음, 끊긴 관계)
  - **B) 상식 Wiki와의 충돌** (예: 분지인데 한랭 기후로 기재됨 → 확인 질문)
  - **C) 미해석/저신뢰 입력** (이미지·메모에서 낮은 확신도로 추출된 항목 확인)

## 5. Functional Requirements

### FR-A. 자료 수집 (Multimodal Ingestion)
- **FR-A1**: 비정형 텍스트 메모를 입력받아 엔티티(장소·인물·사건·사물·관습)와 관계를 추출한다.
- **FR-A2**: 지도 **이미지**를 입력받아 VLM으로 지역·지형(산맥·강·길 등)을 추출한다. (Q4=C)
- **FR-A3**: 범용 **구조화 맵 포맷**(GeoJSON / 노드-엣지 JSON 등)을 입력받아 지역·연결을 직접 구성한다. (Q4=C)
- **FR-A4**: 컨셉아트(이미지)를 입력받아 장소·분위기 등 보조 단서를 추출한다.
- **FR-A5**: 추출 항목에 **확신도(confidence)**를 부여하고, 저신뢰 항목은 보강 Q&A 후보로 표시한다.
- **FR-A6 (디지털 트윈)**: 동일 수집 파이프라인을 **실세계 지도·텍스트**에도 적용해 상식 Wiki(실세계 prior KB)를 구성할 수 있다. (CL2)

### FR-B. 토폴로지 생성 (Connection-Network Topology)
- **FR-B1**: 지도/입력에서 **지역 단위를 식별**하고, **계층 구조**(예: 대륙 > 지방 > 마을 > 구역)로 노드를 구성한다. (Q1=B)
- **FR-B2**: 지형 제약(산맥·강·길·교역로)을 반영한 지역 간 **연결 그래프**(인접성·접근성·단절성)를 생성한다.
- **FR-B3**: 상식 Wiki를 참조해 **연결 강도(가중치)**를 산정한다 (예: 산맥 개입 → 약화). (CL3=C, 역할①)

### FR-C. 온톨로지 / 지식 그래프 (Ontology)
- **FR-C1**: 추출 엔티티(장소·인물·사건·사물·관습)와 그 관계를 지식 그래프로 구성한다.
- **FR-C2**: 각 지식 항목을 토폴로지상의 **지역 노드에 귀속(scoping)**시킨다. 계층 스코프 상속을 지원한다. (Q1=B)
- **FR-C3**: 상식 Wiki를 참조해 **고증 지식을 추론·생성**해 그래프에 추가한다 (출처/근거 표시). (CL3=C, 역할②)

### FR-D. 컨센서스 모델링 (Consensus & Distortion)
- **FR-D1**: 지역 간 연결 강도에 따라 지식의 **공유·전파·미지** 범위를 결정한다.
- **FR-D2 (하이브리드 계산)**: 지역이 **직접 보유한 지식은 정적 전처리로 저장**하고, **전파·소문 범위는 쿼리 시점에 토폴로지 순회로 계산**한다. (Q3=C)
- **FR-D3 (왜곡 표현)**: 지식 왜곡을 **두 방식 모두**로 표현한다 — 경미한 차이는 **confidence/accuracy 속성**, 내용이 바뀌는 소문은 **별도 variant 노드 + `distorted_from` 관계**. (Q2=C)

### FR-E. 상식 Wiki (Common-sense Prior KB)
- **FR-E1**: 실세계 prior를 가상 세계 그래프와 **동일 포맷**으로 영속 저장하고, 조회·편집할 수 있다. (CL1=B)
- **FR-E2**: 가상 세계 해석 시 상식 Wiki를 prior로 참조해 FR-B3(가중치) 및 FR-C3(고증)을 수행한다.
- **FR-E3**: 상식 Wiki는 LLM 추론으로 보완하되, 가능한 한 재현 가능한 데이터(실세계 디지털 트윈)에 근거한다. (CL2=B)

### FR-F. 지식 보강 Q&A (Knowledge Augmentation)
- **FR-F1**: 시스템이 그래프 빈틈/모순(A), 상식 Wiki 충돌(B), 저신뢰 입력(C)을 탐지해 **보강 질문을 생성**한다. (CL5=A,B,C)
- **FR-F2**: 기획자의 답변을 받아 **그래프를 보강/수정**하고, 변경 사항을 추적한다.
- **FR-F3**: 질문 → 답변 → 보강을 **반복(루프)**하며, 잔여 미해결 항목이 수렴할 때까지 진행한다. (CL4=A)

### FR-G. 검토·편집 인터페이스 (Review/Edit UI) — MVP 포함
- **FR-G1**: 생성된 토폴로지와 지식 그래프를 **시각화**한다(웹). (Q8=B, Q9=C)
- **FR-G2**: 노드·관계·지식 항목을 **편집(추가/수정/삭제)**할 수 있다. (Q9=C)
- **FR-G3**: 지식 보강 Q&A를 UI에서 수행할 수 있다(질문 제시 → 답변 입력). (FR-F 연계)

### FR-H. 쿼리 API (Query API)
- **FR-H1**: "지역 X에 거주하는 NPC가 아는 지식"을 반환하는 REST API를 제공한다. (Q8/Q10=A)
- **FR-H2**: 응답에서 **공유 지식과 지역 고유 지식을 구분**해 반환한다. (성공 기준 §8)
- **FR-H3**: 응답은 **JSON**(지식 항목 + 메타데이터: 스코프, confidence, variant/소문 여부, 출처). (Q10=A)

### FR-I. 저장/영속화 (Persistence)
- **FR-I1**: 토폴로지 + 온톨로지 + 상식 Wiki를 **Neo4j**(그래프)에 저장한다. (Q6/CL6=B)
- **FR-I2**: 의미 검색(추출 엔티티↔Wiki/기존 지식 매칭, 유사 지식·고증 검색)을 위해 **OpenSearch**(벡터 + BM25 하이브리드)를 둔다. (CL6=B)

## 6. Non-Functional Requirements

### NFR-A. 기술 스택 (Tech Stack)
- **언어/런타임**: Python 3.11+ (Q5=A)
- **백엔드 API**: FastAPI (Q8=B)
- **프론트엔드**: React (검토·편집 UI) (Q8=B, Q9=C)
- **그래프 저장소**: Neo4j (Q6/CL6=B)
- **검색/벡터**: OpenSearch (하이브리드 BM25 + vector) (CL6=B)
- **실행 환경**: 로컬 개발 + **Docker Compose** (앱 + Neo4j + OpenSearch) (Q11=A)

### NFR-B. LLM / VLM
- **NFR-B1**: 멀티모달 해석(텍스트→엔티티/관계, 이미지→지형/장소)에 LLM/VLM을 사용한다.
- **NFR-B2 (제공자 추상화)**: 특정 제공자에 비종속되도록 **추상화 계층(provider interface)**을 둔다. (Q7=D)
- **NFR-B3 (기본 구현)**: 기본 구현은 **OpenAI** (사용자 API 키 보유). 추상화를 통해 교체 가능. (Q7=B→D)

### NFR-C. 품질 / 테스트
- **NFR-C1 (Security Extension)**: **OFF** — PoC/프로토타입 단계로 SECURITY 규칙 미적용. (Q-Security=B)
- **NFR-C2 (Property-Based Testing)**: **Partial** — 순수 함수와 직렬화 round-trip 에 한해 PBT 적용 (그래프 직렬화·컨센서스 계산 로직 검증). (Q-PBT=B)
- **NFR-C3 (재현성)**: 상식 Wiki 기반 추론은 가능한 한 재현 가능하도록 근거(출처) 기록.

### NFR-D. 입력 신뢰성 / 휴먼-인-더-루프
- **NFR-D1**: 입력 자료는 비정형이며 품질이 일정하지 않다고 가정한다. 해석 실패·저신뢰 시 **기획자 확인 루프**(FR-F)로 처리한다. (제약 §9)

### NFR-E. 성능
- **NFR-E1**: 직접 보유 지식은 정적 전처리로 빠른 쿼리, 전파/소문은 쿼리 시점 계산(하이브리드)으로 유연성 확보. (FR-D2)

## 7. Success Criteria

- **SC-1**: 샘플 세계관 자료(메모 + 지도 1장)를 입력하면, 사람의 추가 작업 없이 **지역 토폴로지 + 지역별 스코프가 지정된 지식 그래프**가 생성된다. (단, 보강 Q&A는 선택적 향상 단계.)
- **SC-2**: 서로 다른 두 지역에 대해 쿼리 시 **공유 지식과 지역 고유 지식이 구분**되어 반환된다.
- **SC-3**: 기획자가 기존 수동 스크립트 작성 대비 NPC 지식 구성 시간을 체감 가능하게 단축한다.
- **SC-4 (신규)**: 상식 Wiki를 활용해 입력에 명시되지 않은 **고증 지식이 1건 이상 자동 생성**되고, 지형 제약이 토폴로지 연결 강도에 반영된다.

## 11. Assumptions & Constraints (§9)

- 입력 자료는 비정형이며 품질이 일정하지 않다(해석 실패 시 보강 Q&A 루프 필요).
