# User Stories — Locus (Purpose Restructure, 2026-09-29)

> 이 파일은 2026-06 스토리(9 Epic · 30 스토리)를 **대체**한다. 옛 내용은 git 이력(`ee61277` 이전)에 있다.
> 근거: `inception/requirements/purpose-restructure-requirements.md`(승인), `inception/plans/purpose-restructure-story-generation-plan.md`(승인, SP-R1=C / SP-R2=A / SP-R3=A).

**목적 문장**: Locus는 세계관 자료로 월드를 만들고, 그 월드 안에서 소문과 사건이 지형을 따라 퍼지며 지역마다 NPC가 다르게 아는 것을 직접 겪는 솔로 TRPG다.

**읽는 법**
- Epic E1~E6은 요구사항 §6 "핵심 경험 흐름" 순서다. 위에서 아래로 읽으면 데모 대본이 된다. E7~E9는 조력자(enabler) Epic으로, 내부 작업을 관람자·플레이어의 가치로 표현했다.
- 스토리 머리: `US-<epic>.<n> 제목 — 우선순위 · 페르소나 · FR 태그`.
- 우선순위: **P0** 이번 사이클 필수 / **P1** 이번 사이클, 유닛 순서상 뒤 / **P2** 시간이 남으면.
- 수용 기준은 Given/When/Then. 가정 A-1~A-5(요구사항 §9)는 해당 수용 기준에 `[A-n]`으로 표시했다.
- 총 **48 스토리** (P0 36 · P1 11 · P2 1). E2(월드 만들기)는 가장 큰 영역이라 8개다.
- **변경 (2026-09-29, Application Design 피드백)**: 플레이어의 행적이 소문이 된다(요구사항 부록 A). US-4.4 · US-4.5 · US-5.6 · US-6.5 · US-8.6 추가. 이 다섯이 레거시 Locus와 갈라지는 지점이다.

## E1 — 띄우기·둘러보기 · P-Viewer

관람자가 저장소를 열어 목적을 읽고, 한 번에 데모를 띄워 둘러본다.

### US-1.1 한 번에 기동한다 — P0 · P-Viewer · FR-H2, NFR-4
관람자로서 `.env` 두 값만 채우고 명령 하나로 앱과 UI를 띄우고 싶다. 그래야 코드를 읽기 전에 써 볼 수 있다.
- **Given** 새 머신에 저장소를 clone하고 `.env`에 `NEO4J_PASSWORD`, `SESSION_DB_PASSWORD`만 채웠다 **When** `docker compose --profile service up -d`를 실행한다 **Then** neo4j·opensearch·postgres·app·web이 모두 healthy가 되고 `http://localhost:3000`이 열리며 `/health`가 `ok`를 돌려준다.
- **Given** 백엔드 이미지를 빌드한다 **When** 컨테이너가 `uvicorn api.main:app`을 실행한다 **Then** `api` 패키지를 찾지 못해 실패하지 않는다(이미지에 `api/` 포함, `.dockerignore`로 `.venv`·`data` 제외).
- **Given** README의 기동 절 **When** 적힌 명령을 그대로 따라 한다 **Then** 없는 프로파일(`tools`)이나 빠진 필수 값 때문에 막히지 않는다.

### US-1.2 README 첫 화면에서 목적을 읽는다 — P0 · P-Viewer · FR-H1, NFR-8
관람자로서 README를 1분 읽고 이 프로젝트가 무엇인지 알고 싶다.
- **Given** README를 연다 **When** 첫 화면을 읽는다 **Then** 첫 줄이 목적 문장(§0)이고, 이어서 핵심 경험 흐름 6단계, 스크린샷(자리), 기동 명령이 보인다.
- **Given** README 디렉터리 절 **When** `locus/` 최상위 패키지와 비교한다 **Then** 이름과 설명이 실제와 일치한다(RE가 찾은 낡은 항목 10개가 없다).
- **Given** README **When** 끝까지 읽는다 **Then** "진행 중 기능" 절에서 옮겨 두기만 한 기능(FR-I)이 무엇인지 알 수 있다.

### US-1.3 원클릭 데모 월드를 불러온다 — P0 · P-Viewer · FR-B3
관람자로서 버튼 하나로 플레이할 만한 월드를 얻고 싶다. 그래야 자료를 준비하지 않아도 바로 플레이할 수 있다.
- **Given** 빈 world_id를 고른 상태 **When** "데모 월드 불러오기"를 누른다 **Then** 지역 10~15개 `[A-4]`, 계층 2~3단, 막힌 길·강·길이 섞인 연결, 지역별 지식, 지역마다 NPC 1~3명, 사건 씨앗 2~3개가 지도에 나타난다.
- **Given** 데모 월드 불러오기 **When** 백엔드 호출을 관찰한다 **Then** LLM 호출은 0회다(World File 로드).
- **Given** 이미 같은 world_id에 월드가 있다 **When** 데모를 다시 불러온다 **Then** 교체 확인을 받은 뒤 기존 월드를 지우고 로드한다(두 벌이 되지 않는다).

### US-1.4 API 키 없이도 둘러볼 수 있다 — P1 · P-Viewer · NFR-4
관람자로서 OpenAI 키가 없어도 지도와 에디터는 보고 싶다.
- **Given** `OPENAI_API_KEY`가 비어 있다 **When** 앱을 띄우고 데모 월드를 불러온다 **Then** 지도·지역 화면·에디터가 열린다.
- **Given** 키가 비어 있다 **When** NPC 대화나 턴 진행을 시도한다 **Then** "LLM 키가 필요합니다"라는 안내가 뜨고 500 오류는 나지 않는다.

## E2 — 월드 만들기 · P-Builder

제작자가 자료를 올리거나 직접 그려 월드를 만들고 다듬는다.

### US-2.1 자료를 올려 월드를 자동 구성한다 — P0 · P-Builder · FR-B1
제작자로서 메모·지도 이미지·구조화 지도를 올리면 초안 월드가 나오길 바란다.
- **Given** 에디터의 "자료로 만들기" 화면 **When** 메모 텍스트 2개, 지도 이미지(PNG) 1개, 구조화 지도 JSON 1개를 올리고 빌드한다 **Then** 지역·연결·엔티티·지식이 생성되어 지도에 나타난다.
- **Given** 지도 이미지 업로드 **When** 요청이 전송된다 **Then** 이미지는 multipart 또는 base64로 실려 VLM 경로가 실제로 실행된다(현재 `list[bytes]` JSON 결함 A7 해소).
- **Given** 빌드 완료 **When** 리포트를 본다 **Then** 지역·연결·지식 수, 경고 목록(계층·연결 후보 경고 포함), 스코프 못 한 지식 수, LLM 호출 수가 보이고 `ok`가 실제 상태를 반영한다.

### US-2.2 지도에서 지역과 연결을 직접 그린다 — P0 · P-Builder · FR-B2
제작자로서 지도 위에서 지역을 놓고 연결을 그어 토폴로지를 손으로 만들고 고치고 싶다.
- **Given** 에디터 모드의 지도 **When** 빈 곳을 눌러 지역을 추가하고 이름·레벨·부모·설명을 입력한다 **Then** 지역 노드가 생기고 저장된다.
- **Given** 지역 둘 **When** 하나에서 다른 하나로 연결을 긋고 종류(adjacent/route/river/blocked)와 가중치를 정한다 **Then** 양방향 `CONNECTED_TO`가 생기고 선 모양이 종류·가중치를 반영한다.
- **Given** 지역을 클릭만 한다 **When** 드래그하지 않는다 **Then** 백엔드에 저장 요청이 가지 않는다(RE B7).
- **Given** 지역 삭제 **When** ✕를 누른다 **Then** 확인 대화가 뜨고, 확인 뒤에만 지운다. 붙어 있던 연결·스코프·NPC 처리 방식이 확인 문구에 보인다.

### US-2.3 지식과 스코프를 편집한다 — P0 · P-Builder · FR-B2, FR-B5
제작자로서 지역이 무엇을 아는지 직접 쓰고 고치고, 지역을 못 찾은 지식도 자리에 놓고 싶다.
- **Given** 지역을 선택했다 **When** "지식 추가"로 제목·진술을 쓰고 저장한다 **Then** 그 지역에 DIRECT 스코프로 붙는다.
- **Given** 빌드 뒤 지역을 못 찾은 지식이 있다 **When** 에디터의 "스코프 없음" 목록을 본다 **Then** 그 지식들이 보이고, 지역을 골라 스코프를 지정할 수 있다(RE A4 — 더 이상 조용히 사라지지 않는다).
- **Given** 지식 편집 **When** 진술을 고친다 **Then** 검색 색인도 함께 갱신되고 스코프는 유지된다.

### US-2.4 지역에 NPC를 배치한다 — P0 · P-Builder · FR-F1, FR-F2
제작자로서 지역마다 살고 있는 NPC를 만들고 싶다. 그래야 플레이어가 대화할 상대가 있다.
- **Given** 지역을 선택했다 **When** "NPC 추가"로 이름·역할·설명을 쓰고 저장한다 **Then** `:NPC` 노드가 그 지역에 `LIVES_IN`으로 붙고 지역 화면의 NPC 목록에 나타난다.
- **Given** NPC가 있다 **When** 편집·삭제한다 **Then** 변경이 저장되고, 삭제는 확인을 거친다.
- **Given** 데모 월드 **When** 불러온다 **Then** NPC가 지역마다 1~3명 들어 있다.

### US-2.5 NPC 초안을 제안받는다 — P1 · P-Builder · FR-F3
제작자로서 지역 지식에 맞는 NPC를 LLM이 먼저 제안해 주면 받아들이고 싶다.
- **Given** 지역을 선택했다 **When** "NPC 제안"을 누른다 **Then** 그 지역의 지식을 반영한 NPC 초안 1~3명(이름·역할·설명)이 보인다.
- **Given** 초안 목록 **When** 하나를 "받아들이기"한다 **Then** 그 NPC만 저장된다. 나머지는 저장되지 않는다.
- **Given** LLM 호출 실패 **When** 제안을 누른다 **Then** 빈 목록과 안내가 뜨고 오류로 끝나지 않는다.

### US-2.6 보강 Q&A로 빈틈을 채운다 — P0 · P-Builder · FR-B6
제작자로서 시스템이 찾은 빈틈(지식 없는 지역, 저신뢰 항목, 고아 엔티티)을 질문으로 받고, 답하면 실제로 반영되길 바란다.
- **Given** 빌드된 월드 **When** "빈틈 찾기"를 누른다 **Then** 질문마다 대상(지식·엔티티·지역 이름과 id)이 함께 보인다.
- **Given** 질문 하나 **When** 선택지(confirm / edit / remove / add / ignore, 고정 enum)를 고른다 **Then** 답이 그래프에 적용되고 무엇이 바뀌었는지 보인다(RE B1 — 빈 노드가 생기지 않는다).
- **Given** 방금 적용한 답 **When** "되돌리기"를 누른다 **Then** 같은 보강 실행 안에서 바뀐 것이 되돌아가고 404가 나지 않는다(RE B2).
- **Given** 대상이 Entity인 질문 **When** confirm 또는 edit를 고른다 **Then** 500이 나지 않고 Entity가 적절히 갱신된다(RE B3).
- **Given** wiki 충돌 탐지 **When** 지역 속성에 `terrain_kind`가 있다 **Then** 탐지기가 그 키를 읽어 충돌을 찾는다(RE B5).

### US-2.7 빌드를 믿을 수 있다 — P0 · P-Builder · FR-B4, FR-B5
제작자로서 자료를 여럿 올리거나 다시 빌드해도 연결이 사라지거나 월드가 두 벌이 되지 않길 바란다.
- **Given** 메모가 "Aldermoor"를 대륙으로 말하고 구조화 지도도 같은 대륙과 연결 1개를 담는다 **When** 빌드한다 **Then** 연결이 남는다(RE A1 — 병합 시 힌트 보존). 경고가 필요하면 리포트에 적힌다.
- **Given** 메모 두 개가 같은 인물 "Mayor Tomas"를 말한다 **When** 빌드한다 **Then** 엔티티는 하나이고 관계·ABOUT 엣지가 모두 그 하나를 가리킨다(RE A2).
- **Given** 같은 world_id에 월드가 있다 **When** 다시 빌드한다 **Then** 교체 확인 뒤 기존 노드를 지우고 새로 만든다. 노드 수가 두 배가 되지 않는다(RE A3).
- **Given** 이름이 같고 레벨이 다른 지역 둘("Riverton" town과 "Riverton" province) **When** 부모·힌트·스코프를 해석한다 **Then** 결과가 결정적이고 규칙이 문서에 있다(RE A11).

### US-2.8 wiki 근거를 본다 — P1 · P-Builder · FR-B7
제작자로서 연결 가중치와 고증 지식이 어떤 상식 prior에 근거했는지 보고 싶다.
- **Given** 빌드된 월드 **When** 에디터의 "상식 wiki" 탭을 연다 **Then** 이 월드의 WikiPrior 목록(조건→효과, 도메인, 신뢰도)이 보인다.
- **Given** 연결 하나를 선택했다 **When** 상세를 본다 **Then** 근거 문구와 참조된 prior가 보인다. 참조가 끊긴 prior는 "저장되지 않은 근거"로 표시된다(RE A9).

## E3 — 세션 시작·이동 · P-Player

플레이어가 캐릭터로 월드에 들어가 지역을 오간다.

### US-3.1 세션을 열고 캐릭터를 놓는다 — P0 · P-Player · FR-C1
플레이어로서 저장된 월드에서 새 판을 시작하고 시작 지역을 고르고 싶다.
- **Given** 저장된 월드 **When** "새 세션"을 누르고 캐릭터 이름과 시작 지역을 고른다 **Then** 세션이 turn 0으로 열리고 플레이어가 그 지역에 있다.
- **Given** 플레이어 상태 **When** 페이지를 새로 고친다 **Then** 이름·현재 지역·턴 수가 그대로다(PostgreSQL 저장).
- **Given** 캐릭터 만들기 화면 **When** 항목을 본다 **Then** 이름과 시작 지역만 있다 `[A-3]`. 스탯·인벤토리는 없다.

### US-3.2 현재 지역 화면을 본다 — P0 · P-Player · FR-C5, FR-D3
플레이어로서 지금 있는 곳이 어떤 곳이고, 누가 있고, 무슨 이야기가 들리고, 어디로 갈 수 있는지 한 화면에서 보고 싶다.
- **Given** 세션 중 **When** 현재 지역 화면을 본다 **Then** 지역 이름·설명·계층 위치(예: Aldermoor > Greenvale > Riverton), NPC 목록, 들리는 이야기, 이동 가능한 연결이 보인다.
- **Given** 들리는 이야기 **When** 항목을 본다 **Then** 정적 지식과 소문이 구분되고, 소문에는 왜곡 정도가 표시된다.
- **Given** 화면 어디서든 **When** 지역을 가리킨다 **Then** UUID가 아니라 이름이 보인다.

### US-3.3 연결을 따라 이동한다 — P0 · P-Player · FR-C2
플레이어로서 지도에서 이어진 곳으로만, 길의 상태에 따라 시간을 들여 이동하고 싶다. 그래야 공간이 뜻을 갖는다.
- **Given** 현재 지역 **When** 이동 목록을 본다 **Then** `CONNECTED_TO`로 이어진 지역만 나오고, 각 항목에 종류와 예상 턴 비용이 보인다.
- **Given** 가중치가 다른 연결 둘 **When** 비용을 비교한다 **Then** 가중치가 낮은 연결의 비용이 더 크거나 같다 `[A-5]` (단조성, PBT-03). 정확한 공식은 Functional Design에서 정한다.
- **Given** `blocked` 연결 **When** 이동을 시도한다 **Then** 지나갈 수 없다고 표시되고 이동하지 않는다 `[A-2]`.
- **Given** 이동을 확정한다 **When** 처리가 끝난다 **Then** 현재 지역이 바뀌고 비용만큼 턴이 흐른다.

### US-3.4 행동이 시간을 흐르게 한다 — P0 · P-Player · FR-C3, NFR-3
플레이어로서 내가 움직이고 말하는 동안 세계도 움직이길 바란다.
- **Given** 세션 중 **When** 이동·대화 마침·기다리기 중 하나를 한다 **Then** 정해진 턴이 소모되고, 턴마다 기존 턴 엔진(사건 적용 → 소문 → 되먹임 → 지지도 → 가지치기 → 승격)이 돈다.
- **Given** 턴이 흐른 뒤 **When** 결과를 본다 **Then** 플레이어 시점의 짧은 요약(내가 있는 지역과 이웃에서 일어난 일)이 보인다.
- **Given** 이동 요청 **When** 화면 전환을 기다린다 **Then** 지역 화면은 LLM을 기다리지 않고 즉시 바뀐다. 턴 처리(LLM 포함)는 진행 표시와 함께 뒤따른다.
- **Given** GM 모드 **When** 수동 "턴 진행"을 누른다 **Then** 같은 엔진이 돈다(기존 기능 유지).

## E4 — NPC 대화 · P-Player

플레이어가 지역 NPC와 대화하며, NPC는 자기 지역에서 알 수 있는 것만 안다.

### US-4.1 지역 NPC와 대화한다 — P0 · P-Player · FR-C4, FR-G3
플레이어로서 이 지역 사람에게 말을 걸고 자유롭게 묻고 싶다.
- **Given** 현재 지역의 NPC 목록 **When** 한 명을 고른다 **Then** NPC 소개와 함께 대화 화면이 열린다.
- **Given** 대화 화면 **When** 자유 텍스트로 묻는다 **Then** NPC가 자기 역할·설명에 맞는 말투로 표시 언어(기본 한국어)로 답한다 `[A-1]`.
- **Given** 한 번의 질문 **When** 백엔드 호출을 관찰한다 **Then** LLM 호출은 1회다(번역 경로를 거치지 않는다).
- **Given** 대화를 이어간다 **When** 같은 세션에서 같은 NPC를 다시 찾는다 **Then** 이전 대화가 저장되어 열람하거나 이어갈 수 있다.

### US-4.2 NPC는 자기 지역에서 알 수 있는 것만 안다 — P0 · P-Player · FR-F4
플레이어로서 NPC가 전지전능하지 않고, 사는 곳에 따라 아는 것이 다르길 바란다. 이것이 Locus의 핵심이다.
- **Given** 지역 R의 NPC **When** 대화 컨텍스트를 만든다 **Then** R의 정적 지식(direct + inherited + global)과 R의 활성 세션 소문, NPC 자신의 설명만 들어간다.
- **Given** 어떤 월드·세션·지역이든 **When** 컨텍스트를 만든다 **Then** R에서 알 수 없는 지식 id는 컨텍스트에 없다(불변식, PBT-03, 도메인 생성기 사용 PBT-07).
- **Given** 컨텍스트에 없는 사실을 묻는다 **When** NPC가 답한다 **Then** 모른다고 하거나 소문대로 말하고, 지어내지 않는다(프롬프트 가드 + 예시 테스트).
- **Given** 이 계산 **When** 코드 위치를 본다 **Then** I/O 없는 순수 함수이고 `knowledge` 경계의 합의 결과와 `play` 경계의 소문을 입력으로 받는다.

### US-4.3 소문은 왜곡된 대로 전한다 — P0 · P-Player · FR-C4
플레이어로서 먼 곳의 사건은 이 지역 사람들이 들은 대로, 틀린 채로 듣고 싶다.
- **Given** 지역 R에 왜곡도 0.7의 소문 "시장이 불탔다 → 폭동으로 시장이 무너졌다" **When** 그 사건을 묻는다 **Then** NPC는 왜곡된 문장의 내용을 전하고, 원문(캐노니컬 지식)은 말하지 않는다.
- **Given** 왜곡도가 높은 소문 **When** NPC가 전한다 **Then** "들었다", "확실하진 않지만" 같은 전언 표현이 붙는다.
- **Given** 승격된 소문(support ≥ 기준) **When** NPC가 전한다 **Then** 확신하는 말투로 사실처럼 말한다.

### US-4.4 내가 한 말과 일의 소문 가치는 NPC가 정한다 — P0 · P-Player · FR-C8, FR-C10 (변경 2026-09-29)
플레이어로서 내가 NPC에게 한 말과 그 지역에서 한 일이 그 사람 눈에 전할 만하면 소문이 되고, 아니면 잊히길 바란다. 모든 말이 소문이 되면 이상하다.
- **Given** 지역 R에서 NPC N과 대화하고 마친다 **When** 대화 마침(`EndTalk`)이 처리된다 **Then** 이 대화의 행적(도착, 내가 말한 내용의 요약, 이 지역에서 선언한 행동)마다 N의 판단(`noteworthy`, `salience`, `slant`, `retelling`)이 N의 성격·역할·지역 지식을 반영해 만들어진다(LLM 1회).
- **Given** N이 `noteworthy=false`로 판단한 행적 **When** 턴이 흐른다 **Then** 그 행적에서 소문이 생기지 않는다.
- **Given** N이 `noteworthy=true`로 판단한 행적 **When** 다음 턴 처리 **Then** N의 `retelling`을 원문으로 한 소문이 R에 생기고, 출처는 `deed`(행적 id, N id)로 남는다.
- **Given** 내가 NPC에게 사실이 아닌 주장을 했다 **When** NPC가 그것을 전할 만하다고 판단한다 **Then** 그 주장이 소문으로 퍼질 수 있다(의도적으로 소문을 뿌릴 수 있다).
- **Given** 지역에서 아무와도 대화하지 않았다 **When** 지역을 떠난다 **Then** 그 지역에서의 행적은 소문이 되지 않는다 `[A-6]`.

### US-4.5 행동을 선언하면 세계가 응답한다 — P0 · P-Player · FR-C9 (변경 2026-09-29)
플레이어로서 "시장 광장에서 도둑을 붙잡았다"처럼 내가 하려는 일을 말하면, 세계가 결과를 이야기해 주고 그 일이 내 행적이 되길 바란다.
- **Given** 현재 지역 화면 **When** 자유 텍스트로 행동을 선언한다 **Then** LLM GM이 지역 맥락(지역 지식·NPC·활성 소문)에 맞게 결과를 짧게 서술하고(판정·주사위 없음 `[A-7]`), 서술이 행적(`declared_action`)으로 기록되며, 1턴이 소모된다.
- **Given** 선언 처리 **When** 백엔드 호출을 관찰한다 **Then** 서술 LLM 호출은 1회다.
- **Given** 그 지역에서 이어서 NPC와 대화하고 마친다 **When** NPC가 판단한다 **Then** 선언 행동도 판단 대상이 되어 소문이 될 수 있다(US-4.4).
- **Given** 선언 텍스트가 비었거나 길이 상한을 넘는다 **When** 보낸다 **Then** 400으로 거절된다.

## E5 — 살아 있는 세계·GM 개입 · P-GM

GM 모드로 사건과 소문을 다루고, 세계가 움직이는 원리를 본다.

### US-5.1 GM 모드로 드나든다 — P0 · P-GM · FR-D1
GM으로서 플레이 화면에서 GM 도구로 들어가고, 끝나면 플레이어로 돌아오고 싶다.
- **Given** 플레이어 화면 **When** "GM 모드"를 켠다 **Then** 사건·소문·왜곡도·턴·타임라인 도구가 보이고 플레이어 상태(위치·턴)는 유지된다.
- **Given** GM 모드 **When** 끈다 **Then** 플레이어 화면으로 돌아오고, GM에서 바꾼 것이 현재 지역 화면에 반영되어 있다.
- **Given** GM 도구 **When** 기존 기능을 확인한다 **Then** 사건 생성·제안·승인·해결·폐기, 지역 왜곡도, 소문 생성·재생성(승격 보존)·지지도, 수동 턴 진행, 타임라인, 지역별 변동 알림이 모두 있다.

### US-5.2 월드를 아는 사건을 제안받고 승인한다 — P0 · P-GM · FR-D2
GM으로서 LLM이 이 월드의 지역과 사정을 반영한 사건을 제안하길 바란다.
- **Given** 세션 중 **When** "사건 제안"을 누른다 **Then** 제안 프롬프트에 지역 이름·설명, 최근 사건, 주요 지식이 들어가고(UUID만 넣지 않는다), 제안된 사건은 실제 지역 이름을 가리킨다.
- **Given** `n` 파라미터 **When** 상한(예: 5)을 넘겨 요청한다 **Then** 400 또는 상한으로 잘린다.
- **Given** 제안된 사건 **When** 승인·폐기한다 **Then** 승인은 ACTIVE로 바뀌고 타임라인에 "승인"으로 기록된다(EVENT_CREATED 재사용 대신 구분). 폐기도 기록된다.

### US-5.3 소문과 왜곡도를 조정한다 — P0 · P-GM · FR-D1, FR-D5
GM으로서 지역의 왜곡도와 소문의 지지도를 밀고 당기며 세계를 조정하고 싶다.
- **Given** 지역 선택 **When** 왜곡도 슬라이더를 움직인다 **Then** 값이 저장되고 다음 소문 생성 체인의 강도에 반영된다.
- **Given** 소문 하나 **When** 지지도를 바꾼다 **Then** 저장되고 다음 턴의 승격 판정에 쓰인다.
- **Given** 슬라이더 **When** 키보드·터치로 값을 바꾼다 **Then** 마우스와 같이 저장된다(P1).
- **Given** 지역 소문 재생성 **When** 확인한다 **Then** 승격된 소문은 남고 나머지만 새로 만든다(기존 기능 유지).

### US-5.4 타임라인과 지역별 변동을 이름으로 본다 — P0 · P-GM · FR-D1, FR-D3
GM으로서 턴마다 어디서 무엇이 바뀌었는지 지역 이름으로 읽고 싶다.
- **Given** 턴이 흐른 뒤 **When** 타임라인을 본다 **Then** 각 항목이 지역 이름과 한국어 템플릿으로 읽힌다.
- **Given** 턴 결과 **When** 알림을 본다 **Then** 지역별로 승격·강등·가지치기·사건 적용·해결·새 소문 수가 이름과 함께 뜬다.
- **Given** 플레이어 모드 **When** 같은 기록을 본다 **Then** 플레이어 시점으로 걸러진 로그(내가 있던 지역과 겪은 일)만 보인다(FR-C6, P1).

### US-5.5 세계 상태를 지도 위에서 본다 — P1 · P-GM · FR-D4
GM으로서(그리고 관람자로서) 왜곡도와 소문이 지도 위에서 어떻게 번지는지 보고 싶다.
- **Given** GM 모드의 지도 **When** "세계 상태" 오버레이를 켠다 **Then** 지역마다 왜곡도(색)와 활성 소문 수·승격 수(크기 또는 숫자)가 표시된다.
- **Given** 사건을 승인하고 턴을 세 번 넘긴다 **When** 오버레이를 본다 **Then** 사건 지역에서 연결을 따라 왜곡도가 번진 모양이 보인다.

### US-5.6 GM이 행적과 그 소문의 퍼짐을 보고 취소한다 — P1 · P-GM · FR-D6 (변경 2026-09-29)
GM으로서 플레이어의 행적이 어떤 NPC의 판단으로 어디까지 퍼졌는지 보고, 과한 것은 없던 일로 하고 싶다.
- **Given** GM 모드 **When** "행적" 패널을 본다 **Then** 행적마다 종류·지역·턴·판단한 NPC·판단 내용·그 행적에서 난 소문이 도달한 지역 목록이 보인다.
- **Given** 행적 하나 **When** "취소"한다 **Then** 그 행적에서 난 소문(전파된 것 포함)이 모두 비활성화되고 타임라인에 `DEED_VOIDED`가 남는다.
- **Given** 사건 제안 **When** 컨텍스트를 본다 **Then** 최근 행적이 들어가 있다(FR-D2 보강).

## E6 — 다시 보기·저장 · P-Player / P-Builder

같은 사건을 다른 지역에서 다르게 듣고, 월드를 저장·불러온다.

### US-6.1 같은 사건을 다른 지역에서 다르게 듣는다 — P0 · P-Player · 목적의 증명 (FR-C, FR-E)
플레이어로서 사건이 난 곳과 산맥 너머에서 같은 일을 다르게 말하는 것을 겪고 싶다. 이 스토리가 Locus의 존재 이유다.
- **Given** 데모 월드, 지역 A(Riverton)에 사건이 일어나 턴이 두 번 흘렀다 **When** A의 NPC에게 그 사건을 묻는다 **Then** 직접 지식으로 정확히 말한다.
- **Given** 같은 세션 **When** 연결이 약하거나 막힌 길 너머 지역 B(Highcrag)로 이동해 그곳 NPC에게 같은 사건을 묻는다 **Then** 왜곡된 소문으로 말하거나 모른다고 한다.
- **Given** 이 시나리오 **When** 데모 스크립트로 실행한다 **Then** 재현 가능하고(데모 월드 고정 + 사건 씨앗) Build&Test의 라이브 시나리오에 들어간다.

### US-6.2 월드를 World File로 저장한다 — P0 · P-Builder · FR-B8
제작자로서 만든 월드를 파일로 내려받아 보관하고 싶다.
- **Given** 편집한 월드 **When** "저장"을 누른다 **Then** `format_version`, 월드 메타(이름·설명), 지역·연결·엔티티·관계·지식·스코프·WikiPrior·NPC가 담긴 JSON이 내려온다.
- **Given** World File **When** 내용을 본다 **Then** 기존 export JSON의 상위 호환이고 사람이 읽을 수 있다.
- **Given** CLI **When** `locus export --world X --out file.json`을 실행한다 **Then** 같은 포맷이 나온다.

### US-6.3 World File을 불러온다 — P0 · P-Builder · FR-B8, NFR-9
제작자로서 저장한 월드를 그대로 다시 열고 싶다.
- **Given** World File **When** 에디터에서 "불러오기"로 올린다(또는 CLI `locus import`) **Then** LLM 호출 없이 그래프가 만들어지고 지도에 그대로 나타난다.
- **Given** 임의의 유효한 월드 **When** 저장 → 불러오기 → 저장한다 **Then** 두 파일이 같다(왕복, PBT-02, 도메인 생성기 PBT-07).
- **Given** 같은 world_id에 월드가 있고 열린 세션도 있다 **When** 불러온다 **Then** "기존 월드를 교체하고 열린 세션 N개를 닫습니다" 확인을 받은 뒤 진행한다.
- **Given** `format_version`이 다른 파일 **When** 불러온다 **Then** 지원 여부를 알려 주고, 지원하지 않으면 명확한 오류로 거절한다.

### US-6.4 저장된 월드 목록에서 고른다 — P1 · P-Builder · FR-B9
제작자로서 world_id를 외우지 않고 목록에서 월드를 열고 싶다.
- **Given** 월드가 여럿 저장되어 있다 **When** 시작 화면을 본다 **Then** 이름·지역 수·마지막 수정·열린 세션 수가 보인다.
- **Given** 목록 **When** 하나를 고른다 **Then** 에디터 또는 세션 시작으로 바로 이어진다.

### US-6.5 내 행적을 먼 지역에서 다르게 듣는다 — P0 · P-Player · FR-C8, FR-E7 (변경 2026-09-29)
플레이어로서 내가 리버턴에서 한 일이 며칠 뒤 산 너머 하이크랙에서 부풀려진 소문으로 돌아오는 것을 겪고 싶다. 레거시 Locus와 갈라지는 장면이다.
- **Given** 지역 A에서 행동을 선언하고 NPC와 대화해 그 NPC가 전할 만하다고 판단했다 **When** 턴이 두세 번 흐른다 **Then** A와 연결 가중치가 기준 이상인 이웃 지역 B에 `1 − w`만큼 더 왜곡된 소문이 생기고, B의 NPC가 그것을 전언으로 말한다.
- **Given** A와 막힌 길로만 이어진 지역 C **When** 같은 턴이 흐른다 **Then** C에는 그 소문이 도달하지 않는다(또는 우회로 가중치만큼 늦고 더 왜곡된다).
- **Given** 전파된 소문 **When** 지지도가 오른다 **Then** 승격 규칙을 그대로 따라 그 지역의 "사실"이 될 수 있다.
- **Given** 이 시나리오 **When** 데모 스크립트로 실행한다 **Then** US-6.1과 함께 Build&Test 라이브 시나리오에 들어간다.

## E7 — 조력자: 읽히는 구조 · P-Viewer

코드 배치가 목적을 말하고, 의존 방향이 한 방향이며, 테스트가 그대로 돈다.

### US-7.1 패키지 배치와 이름이 목적을 말한다 — P0 · P-Viewer · FR-A1, FR-A5, FR-A6
관람자로서 `locus/` 최상위만 보고 구조를 짚고, 같은 말이 다른 뜻으로 쓰이지 않길 바란다.
- **Given** `locus/` 최상위 **When** 디렉터리를 본다 **Then** 월드 구성 / 지역 지식 계산 / 플레이 / 로컬라이징 / 공용 다섯 경계가 이름으로 드러난다(정확한 이름은 Application Design).
- **Given** 코드 검색 **When** `rumor`, `distortion_degree`, `session`을 찾는다 **Then** 각 이름은 한 뜻으로만 쓰인다(캐노니컬 거리 소문·경로 감쇠·보강 실행은 다른 이름).
- **Given** API 경로 **When** 라우터를 본다 **Then** 경계에 맞는 접두어(예: `/api/world`, `/api/play`, `/api/gm`)를 쓴다(P1).

### US-7.2 의존 방향이 한 방향이고 경계마다 조립된다 — P0 · P-Viewer · FR-A2, FR-A3, FR-A4
관람자로서 캐노니컬 코드가 세션을 모르고, 한 경계가 없어도 나머지가 뜨길 바란다.
- **Given** import 그래프 검사(테스트) **When** 실행한다 **Then** play → knowledge → shared, world → knowledge → shared, localization → shared 방향만 있고 역방향(예: config → play)이 없다.
- **Given** 캐노니컬 모델·enum **When** 필드를 본다 **Then** `SESSION_*`·`*_ko` 같은 다른 경계의 필드가 없다.
- **Given** 앱 조립 **When** play 경계의 서비스를 주입하지 않고 앱을 만든다 **Then** world·knowledge 라우터는 정상이고 play 라우터만 503이다.
- **Given** PostgreSQL 어댑터·번역 저장 **When** 위치를 본다 **Then** 각각 play·localization 경계 안에 있고, `SessionRepository`는 관심사별 포트로 나뉘어 있다.
- **Given** CLI `init-schema` **When** 실행한다 **Then** 경계별 스키마 초기화가 분리되어 있다(PostgreSQL 없이 캐노니컬만 초기화 가능).

### US-7.3 진행 중 기능이 표시된다 — P1 · P-Viewer · FR-I, FR-H3
관람자로서 무엇이 완성이고 무엇이 진행 중인지 헷갈리지 않길 바란다.
- **Given** README **When** "진행 중 기능" 절을 본다 **Then** 교차 월드 prior 검색, 컨셉아트 수집, LangGraph 래퍼, wiki 순환 구조 개선이 상태와 함께 적혀 있다.
- **Given** 코드 **When** 해당 모듈을 본다 **Then** world 경계 안에 옮겨져 있고 모듈 docstring에 상태가 있다. 삭제된 기능은 없다.
- **Given** UI **When** 진행 중 기능에 닿는 화면이 있다면 **Then** "진행 중" 표시가 붙어 있다.

### US-7.4 기존 테스트가 그대로 GREEN이다 — P0 · P-Viewer · NFR-1
관람자로서(그리고 제작자로서) 경계를 옮겼다고 검증이 사라지지 않길 바란다.
- **Given** 경계 이동 뒤 **When** `pytest`와 `npm test`를 돈다 **Then** 기존 281 + 24개가 import 경로만 바뀐 채 통과하고, 새 테스트가 더해진다.
- **Given** 의도적으로 바꾼 동작(소문 상한, 승격 면제 축소) **When** 관련 테스트를 본다 **Then** 고친 이유가 테스트 docstring 또는 커밋에 적혀 있다.
- **Given** PBT **When** 실패한다 **Then** hypothesis가 seed와 축소된 최소 입력을 출력한다(PBT-08).

### US-7.5 저장소 메타가 서로 맞는다 — P1 · P-Viewer · FR-H4
관람자로서 라이선스·의존성 선언이 어긋나 신뢰를 잃지 않길 바란다.
- **Given** `pyproject.toml`과 `LICENSE` **When** 비교한다 **Then** 같은 라이선스를 말한다.
- **Given** `requirements.txt` **When** `pyproject` 의존성과 비교한다 **Then** 빠진 것이 없다(sqlalchemy·psycopg 포함).
- **Given** `web/` **When** `npm ci`를 새로 실행한다 **Then** peer 의존성 충돌(plugin-react ↔ vite 8)로 실패하지 않는다.

### US-7.6 최소 CI가 돈다 — P2 · P-Viewer · FR-H5
관람자로서 "GREEN"이 수동 주장이 아니라 CI 배지이길 바란다.
- **Given** GitHub Actions 워크플로 **When** push한다 **Then** pytest(hypothesis seed 로그 포함)·vitest·ruff·black·tsc가 돈다.
- **Given** README **When** 상단을 본다 **Then** CI 상태 배지가 있다.

## E8 — 조력자: 폭주하지 않는 세계 · P-Player / P-GM

시뮬레이션이 상한 안에서 돌고, 한 번에 하나씩 진행된다.

### US-8.1 소문이 턴마다 폭주하지 않는다 — P0 · P-Player · FR-E1, NFR-5
플레이어로서 몇 턴 지났다고 세계가 소문으로 넘치거나 LLM 비용이 폭발하지 않길 바란다.
- **Given** 지역 1개, 지식 3개, persistent WAR 사건(강도 0.5) **When** 턴을 4번 넘긴다 **Then** 턴당 LLM 호출이 정한 상한 이하이고(RE 재현치 9→36→144→576이 아니다), 지역당 활성 소문 수가 상한 이하다.
- **Given** 임의의 세션 상태 **When** 턴을 한 번 넘긴다 **Then** "새 소문 수 ≤ 지역별 상한", "LLM 호출 ≤ 상한" 불변식이 성립한다(PBT-03).
- **Given** 이미 파생 소문을 낳은 캐노니컬 지식 **When** 다음 턴에 원본을 모은다 **Then** 같은 지식이 다시 씨앗이 되지 않는다.
- **Given** 턴 결과 **When** 본다 **Then** 이 턴의 LLM 호출 수가 표시된다.

### US-8.2 승격 소문 하나가 지역 감쇠를 끄지 않는다 — P0 · P-Player · FR-E2
플레이어로서 사건이 끝나면 소문도 잦아들길 바란다.
- **Given** 지역에 승격 소문 1개와 비승격 소문 여럿, 사건은 해결됨 **When** 턴을 넘긴다 **Then** 비승격 소문의 지지도가 감쇠하고 기준 아래는 가지치기된다. 승격 소문은 예외다.
- **Given** 되먹임으로 올라간 왜곡도 **When** 사건이 해결되고 소문이 잦아든다 **Then** 왜곡도가 올라가기만 하지 않는다(복원 또는 상한).

### US-8.3 턴 진행은 한 번에 하나다 — P0 · P-GM · FR-E3
GM으로서 턴 진행 버튼을 두 번 눌러도 세계가 두 번 움직이지 않길 바란다.
- **Given** 같은 세션 **When** 턴 진행 요청 둘이 동시에 들어온다 **Then** 하나만 실행되고 다른 하나는 409 또는 첫 요청 결과를 받는다.
- **Given** 턴 진행 중 LLM 호출 **When** 저장 트랜잭션을 본다 **Then** LLM 호출은 트랜잭션 밖에서 끝나고 상태 저장은 가능한 한 하나의 트랜잭션이다.
- **Given** 세션 시작 **When** 지역별 왜곡도를 초기화한다 **Then** 하나의 트랜잭션이다(RE C4).

### US-8.4 사건 상태와 소문 계보가 온전하다 — P1 · P-GM · FR-E4, FR-E5, FR-E6
GM으로서 상태 전이가 규칙대로 되고 소문의 출처를 따라갈 수 있길 바란다.
- **Given** SUGGESTED 사건 **When** 승인 없이 해결을 시도한다 **Then** 400으로 거절된다.
- **Given** 세션 시작·종료·사건 폐기 **When** 타임라인을 본다 **Then** 각각 기록이 있다.
- **Given** 지역 소문 재생성 **When** 비승격 부모 소문을 처리한다 **Then** 삭제하지 않고 비활성화하여 남은 소문의 `distorted_from_id`가 끊기지 않는다.
- **Given** 세션이 열린 뒤 월드에 지역이 추가됐다 **When** 왜곡도 목록을 본다 **Then** 그 지역도 기본값으로 들어 있다.

### US-8.5 조정값이 한곳에 있다 — P1 · P-GM · FR-A7
GM으로서(그리고 개발자로서) 합의 기준·가중치·이벤트 델타·승격 기준을 한 설정에서 보고 바꾸고 싶다.
- **Given** 설정 코드 **When** 조정값을 찾는다 **Then** 캐노니컬(합의 0.5/0.15, 가중치 표, dedup 0.86)과 플레이(이벤트 델타 0.3, 승격 0.6, 감쇠·상한) 조정값이 설정 객체에 모여 있고 환경 변수로 덮어쓸 수 있다.
- **Given** `ConsensusParams` **When** 사용처를 본다 **Then** 한 곳에서 만들어 주입한다(세 곳에서 따로 만들지 않는다).

### US-8.6 행적 소문의 전파도 상한을 지킨다 — P0 · P-Player · FR-E7, FR-E1 (변경 2026-09-29)
플레이어로서 내 행적 하나가 세계를 소문으로 덮거나 LLM 비용을 폭발시키지 않길 바란다.
- **Given** 지역 10개가 촘촘히 연결된 월드, 행적 소문 1개 **When** 턴을 5번 넘긴다 **Then** 지역마다 그 행적에서 난 소문은 최대 1개이고(같은 행적은 같은 지역에 두 번 퍼지지 않는다), 턴당 전파 LLM 호출은 예산 이하다.
- **Given** 임의의 세션 상태 **When** 전파 단계를 돈다 **Then** "전파 대상 가중치 ≥ 기준", "왜곡도 = max(원본, 1 − w) 이상", "같은 (행적, 지역) 쌍 중복 없음" 불변식이 성립한다(PBT-03, 순수 `plan_spread`).
- **Given** 캐노니컬 기원 소문 **When** 전파 단계를 돈다 **Then** 전파되지 않는다(hearsay 계산과 중복 금지).

## E9 — 조력자: 언어 · P-Player / P-Builder

화면은 한국어, 임베딩 텍스트는 영어, 번역은 어느 경계에서도 쓴다.

### US-9.1 화면은 한국어, 저장 텍스트는 영어다 — P0 · P-Player · FR-G2, C-1
플레이어로서 한국어로 읽고, 제작자로서 벡터 검색이 한 언어로 일관되길 바란다.
- **Given** 지식·소문·엔티티·WikiPrior 생성 **When** 저장된 텍스트를 본다 **Then** 영어다(임베딩 대상은 영어로 생성).
- **Given** 현재 지역 화면·에디터·GM 화면 **When** 텍스트를 본다 **Then** 한국어 번역이 보이고 원문 토글이 있다. 캐노니컬 지식(에디터, 지역 화면)도 번역 대상이다.
- **Given** 번역 캐시에 없는 항목 **When** 화면을 연다 **Then** 원문이 먼저 보이고 백그라운드 번역 뒤 갱신된다(읽기 비차단 유지).

### US-9.2 NPC는 표시 언어로 말한다 — P0 · P-Player · FR-G3
플레이어로서 NPC와 한국어로 대화하되, 대화마다 번역 비용이 두 배 들지 않길 바란다.
- **Given** 표시 언어 설정 = 한국어 **When** NPC가 답한다 **Then** 한국어로 직접 생성된다 `[A-1]`. 대화문은 임베딩하지 않는다.
- **Given** 컨텍스트의 지식·소문(영어) **When** NPC가 인용한다 **Then** 한국어로 자연스럽게 옮겨 말한다.
- **Given** 표시 언어를 영어로 바꾼다 **When** 대화한다 **Then** 영어로 답한다.

### US-9.3 번역은 어느 경계에서도 쓸 수 있다 — P0 · P-Builder · FR-G1, FR-G4
제작자로서 세션이 없어도 에디터의 지식이 번역되길 바란다.
- **Given** localization 경계 **When** 포트를 본다 **Then** 자체 `TranslationRepository`와 서비스가 있고 play 모델을 import하지 않는다.
- **Given** 세션이 하나도 없는 월드 **When** 에디터에서 지식을 본다 **Then** 번역이 동작한다.
- **Given** 같은 항목을 동시에 여러 화면이 요청한다 **When** 워밍이 돈다 **Then** 같은 항목을 두 번 번역하지 않는다(P1).
- **Given** 소문·지식이 삭제됐다 **When** 정리를 돈다 **Then** 고아 번역 행이 남지 않는다(P1).

### US-9.4 UI 라벨이 한 언어로 통일된다 — P1 · P-Player · FR-G5
플레이어로서 화면에 영어 버튼과 한국어 버튼이 섞여 있지 않길 바란다.
- **Given** 모든 화면 **When** 라벨을 훑는다 **Then** i18n 사전에서 오고, 하드코딩 영어(Approve/Discard/Resolve, Load, Build 등)가 없다.
- **Given** 표시 언어 전환 **When** 영어로 바꾼다 **Then** UI 라벨도 함께 바뀐다(사전에 en 항목).

## INVEST 점검

- **Independent**: 스토리마다 수용 기준이 자기 안에서 닫힌다. 의존이 있는 것은 데이터 전제(예: US-6.1은 데모 월드 US-1.3)를 Given에 명시했다.
- **Negotiable**: 이동 비용 공식(US-3.3), 경계 이름(US-7.1), API 접두어는 Functional/Application Design에서 정한다고 적었다.
- **Valuable**: 조력자 Epic도 관람자·플레이어 가치로 썼다("저장소를 읽는다", "세계가 폭주하지 않는다").
- **Estimable**: 각 스토리가 하나의 화면 또는 하나의 규칙 묶음이다. E2가 8개인 것은 에디터가 가장 큰 영역이기 때문이다.
- **Small**: 한 스토리가 한 유닛을 넘지 않도록 잡았다. Units Generation에서 스토리를 나누지 않고 묶기만 하면 된다.
- **Testable**: 모든 수용 기준이 Given/When/Then이고, PBT 대상(US-3.3, US-4.2, US-6.3, US-8.1)은 불변식을 문장으로 적었다.
