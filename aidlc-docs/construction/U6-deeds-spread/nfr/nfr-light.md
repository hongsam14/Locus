## 1. NFR별 적용

| **NFR-2 PBT Partial** | ✅ | TP-U6-1~8을 적용한다. 핵심은 둘이다. `plan_spread` 불변식(TP-U6-1)과, 한 턴 안 지역 상한(TP-U6-8, FR-E1 blocking)이다. 생성기는 `tests/play/strategies.py`를 넓힌다(PBT-07). 넓힐 것은 지역 그래프(막힌 길 섞음), 행적·판단, 행적 기원 소문 체인이다. U5 리뷰 뒤 `rumors_from`은 이미 체인을 만든다. 프로파일 `locus`(`print_blob=True`)로 실패를 재현한다(PBT-08) | 각 TP가 테스트 이름으로 대응(코드 플랜 표) |

## 2. 신뢰성 · 규모
- **실패 격리**
  - 준비 단계에서 LLM이 실패하면 서술은 고정 문구로 대신하고 판단은 기록하지 않는다. 행동은 1턴을 쓰고 끝난다. `llm_failed=true`다.
  - 준비 단계의 DB 쓰기가 실패하면 실행이 실패하고, 보상이 턴·위치를 되돌린다. 그 실행의 행적도 지운다(BR-U6-36).
  - 전파 호출이 실패하면 그 턴의 남은 LLM 작업을 멈춘다(회로 차단, BR-U6-22).
- **동시성**
  - 준비 단계와 턴은 한 실행 = 한 가드 아래다.
  - 취소는 GM 쓰기의 `_idle` 리스 아래에서 읽기부터 커밋까지 한다. 그래서 취소 뒤에 씨앗이나 전파가 새로 나오지 않는다(TP-U6-4).
  - 대화 `say`는 가드 밖이다. 요약 커서(`messages_through`)가 겹친 발언을 잃지 않게 한다.
- **규모(A-4 데모, N6-6)**
  - 한 턴의 추가 읽기는 셋이다. 행적 기원 활성 소문, 씨앗 준비 판단, 판단 기원별 도달 지역이다. 모두 세션 범위이고 색인이 있다.
  - 전파 계획은 부모 소문마다 `best_path_weights` 한 번이다. 데모 규모에서 연결 수백 개 × 부모 수십 개다.
  - 행적·판단 테이블은 보관 정책을 두지 않는다(대화와 같다).

## 3. 기술 스택 결정 (신규 없음)
| 결정 | 선택 | 대안과 까닭 |
|---|---|---|
| 서술·판단 생성 | 기존 `LLMProvider.structured`(+`retry.py`) | 새 어댑터·스트리밍은 범위 밖이다(C-3). 구조화 출력 한 번에 두 값(서술 + 기록, 요약 + 판단 목록)을 받는다 |
| 전파 경로 계산 | 기존 `knowledge.propagation.best_path_weights` | play → knowledge 의존은 경계 규칙 안이다. 새 그래프 라이브러리는 필요 없다 |
| 열 추가 | SQLAlchemy inspector + `ALTER TABLE ADD COLUMN` | Alembic은 인프라와 절차를 더한다. 추가만 하는 열 셋에 과하다(N6-3) |
| 행적·판단 저장 | PostgreSQL 두 테이블 + 기존 UoW | 새 저장소는 C-4 위반이다 |

## 4. 코드 생성 플랜으로 넘기는 것
1. **FD 게이트의 이월 넷**
   - R-10: 이탈 목록의 나머지 세 항목을 적는다. `DeedService` 메서드 이름, 도달 가중치(`w(X)×edge` vs `best_path_weights(origin)[y]`)와 `TP-U6-1(b)`의 의미, `SpreadTarget`·`DeedView`·void 모양이다.
   - R-15: 태어난 턴 감쇠 면제는 **소문 단위**다. `decay_support`에 면제 id 인자를 더하고, 한 지역에 옛 소문과 새 소문이 함께 있는 예제를 둔다.
   - R-16: 발언 판단이 빠지면 `noteworthy=false, salience=0`으로 함께 저장한다.
   - R-17: `SceneBrief` 조립 주체와 의존을 정하고, `lang` 경로(`router → PlayService.act → TurnAdvancer.begin → _start`)를 적는다.
2. **N6-2 길이 상한**: 서술 1,000, 기록·요약·`retelling` 300, `slant` 40. N6-5의 프레이밍 문장.
3. **env 여섯**: `SPREAD_MIN_WEIGHT`·`DEED_SEED_MIN_SALIENCE`·`MAX_SPREAD_PER_REGION_TURN`·`DECLARE_MAX_CHARS`·`NPC_MAX_DEEDS`·`APPRAISAL_MAX_DEEDS`. `env.example`·`operations.md` 갱신 단계.
4. **§1 NFR-3 구조 단언 넷, NFR-6 주입 예제, NFR-9 사라진 지역 예제**를 테스트 단계로.
5. **U5 리뷰의 정리 백로그** 가운데 U6가 같은 곳을 건드리는 것
   - C1: `npcs_here`의 N+1이다. U6의 판단·컨텍스트도 NPC마다 읽는다.
   - C4: "NPC가 이 지역에 있다" 규칙이 세 곳에 있다. U6가 넷째를 더한다.
   - 이 둘은 같은 단계에서 한 곳으로 모을지를 플랜에서 정한다.
