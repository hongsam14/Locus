## 0. 한 문장 목적 (Purpose Statement)

> **Locus는 세계관 자료로 월드를 만들고, 그 월드 안에서 소문과 사건이 지형을 따라 퍼지며 지역마다 NPC가 다르게 아는 것을 직접 겪는 솔로 TRPG다.**

- 만들기: 메모·지도를 올리거나 직접 그려 월드를 구성하고 저장한다.
- 플레이하기: 캐릭터로 지역을 오가며 NPC와 대화한다. NPC는 자기 지역에서 알 수 있는 것만 안다.
- 살아 있기: 턴이 흐르면 사건이 일어나고 소문이 왜곡되어 퍼진다. 필요하면 GM 모드로 세계에 개입한다.

이 문장이 README 첫 줄, `pyproject` description, CLAUDE.md Project Overview에 그대로 들어간다(FR-H1).

- **RE 가정 하나가 뒤집혔다.** RE는 wiki·고증·보강·OpenSearch 색인을 "목적 밖 부가 기능"으로 분류했다. 사용자는 이를 "아직 구현하지 못한 목적 안 기능"으로 봤다. 이 문서는 사용자의 판단을 따른다(§8 FR-I).
- **승인 시 확인할 가정** (§9 참조): A-1 NPC 대화 언어, A-2 막힌 연결 처리, A-3 플레이어 캐릭터 범위, A-4 데모 월드 규모.

## 6. 핵심 경험 흐름 (End-to-End)

이 흐름이 데모에서 끊기지 않고 돌아야 한다(NFR-4). 번호는 FR와 대응한다.

1. **띄우기** — `docker compose --profile service up`으로 앱과 UI가 뜬다. (FR-H2)
2. **월드 만들기** — 원클릭 데모 월드를 부르거나(FR-B3), 메모·지도를 올려 자동 구성한다(FR-B1). 에디터에서 지역·연결·지식·NPC를 고치고(FR-B2·B4), 보강 Q&A로 빈틈을 채운다(FR-B6). 저장한다(FR-B8).
3. **세션 시작** — 저장된 월드에서 세션을 열고, 플레이어의 시작 지역을 고른다. (FR-C1)
4. **플레이** — 현재 지역의 설명·NPC·들리는 소문을 본다(FR-C5). NPC와 대화한다(FR-C4). 연결된 지역으로 이동한다(FR-C2). 이동·행동마다 턴이 흐르고(FR-C3), 사건이 일어나고 소문이 퍼진다(FR-E).
5. **개입** — GM 모드로 전환해 이벤트를 만들거나 승인하고, 왜곡도·지지도를 조정하고, 타임라인을 본다. (FR-D)
6. **다시 보기** — 다른 지역으로 가서 같은 사건을 다르게 말하는 NPC를 만난다. 이것이 Locus가 보여 주려는 것이다.

## 7. 기능 요구사항 (Functional Requirements)

우선순위: **P0** = 이번 사이클에 반드시 / **P1** = 이번 사이클에 넣되 유닛 순서상 뒤 / **P2** = 시간이 남으면.

### FR-A 구조 재정리 (Boundaries)
- **FR-A1 (P0) 모듈 경계를 목적에 맞게 다시 나눈다.** 최소 다음 경계를 둔다. 실제 패키지 이름·배치는 Application Design에서 정한다.
  - **world (월드 구성)**: 수집, 토폴로지, 온톨로지, 상식 wiki, 보강, 편집, 저장·로드, 데모 월드.
  - **knowledge (지역 지식 계산)**: 합의, 월드 로드, 지역 지식 질의. world와 play가 둘 다 읽는 순수 코어.
  - **play (플레이)**: 세션, 플레이어, 이동, 턴, 소문, 이벤트, NPC 대화, GM 도구.
  - **localization**: 번역 캐시. 어느 도메인에도 속하지 않는다.
  - **shared**: 모델, 설정, LLM 포트, 저장소 포트·어댑터.
- **FR-A2 (P0) 역방향 의존을 없앤다.** RE §E의 네 곳이 대상이다: `config → session`, 캐노니컬 enum·뷰의 `SESSION_*`·`*_ko`, `init-schema`의 PostgreSQL 결합, `canonical_known`의 세션 전용성. 의존 방향은 play → knowledge → shared, world → knowledge → shared, localization → shared만 허용한다.
- **FR-A3 (P0) 조립 루트를 경계별로 나눈다.** `api/main.py` 하나가 전부를 엮는 대신, 경계마다 조립 함수를 두고 앱이 이를 합친다. 한 경계의 서비스가 없어도 다른 경계는 503이 되지 않는다.
- **FR-A4 (P0) 저장 어댑터를 경계 안으로 옮긴다.** `postgres_session_repo.py`는 play 경계로, 번역 저장은 localization 경계로 간다. `SessionRepository`는 관심사별 포트로 나눈다(세션·소문·이벤트·타임라인·번역).
- **FR-A5 (P0) 겹치는 용어를 분리한다.** §4 표대로.
- **FR-A6 (P1) API 경로를 경계에 맞춘다.** 예: `/api/world/...`, `/api/play/...`, `/api/gm/...`. Q4=A라 기존 경로 유지 의무는 없다. 프론트 `api.ts`·`types.ts`도 함께 바꾼다.
- **FR-A7 (P1) 조정값을 한곳에 모은다.** 하드코딩 상수(합의 0.5/0.15, 가중치 표, 이벤트 델타, 승격 0.6 등)를 설정 객체로 모아 `Settings`에서 덮어쓸 수 있게 한다. 연구 용도는 아니므로 UI 노출은 하지 않는다.

### FR-B 월드 에디터 (World Editor)
- **FR-B1 (P0) 자료 업로드로 자동 구성한다.** 메모 텍스트, 구조화 지도 JSON, 지도 이미지를 UI에서 올려 빌드한다. 이미지는 base64 또는 multipart로 전송한다(RE A7 수정). 빌드 리포트(경고·오류·스코프 못 한 지식 수)를 UI에 보인다(RE A13).
- **FR-B2 (P0) UI에서 직접 그리고 고친다.** 지역 추가·삭제·이름·레벨·부모·위치, 연결 추가·삭제·종류·가중치(RE B9), 지식 추가·편집·삭제와 지역 스코프 지정, NPC 추가·편집·삭제(FR-F). 지도 클릭이 저장을 일으키지 않는다(RE B7). 삭제는 확인을 거친다(RE B8).
- **FR-B3 (P0) 원클릭 데모 월드.** TRPG에 맞게 키운 데모(지역 10~15개, 계층 2~3단, 연결에 막힌 길·강·길 섞임, 지역별 지식, NPC 각 지역 1~3명, 사건 씨앗 2~3개)를 버튼 하나로 불러온다. LLM 없이 로드된다(저장 포맷 파일). 기존 Aldermoor는 이 데모의 씨앗으로 확장한다.
- **FR-B4 (P0) 재빌드가 월드를 중복시키지 않는다.** 같은 `world_id`로 다시 빌드하면 기존 월드를 지우거나 교체한다(RE A3). 사용자에게 확인을 받는다.
- **FR-B5 (P0) 수집 병합 결함을 고친다.** 지역 병합 시 연결 힌트 보존(RE A1), 엔티티 병합 시 id 재매핑(RE A2), 지역 미해석 지식을 "스코프 없음"으로 보이게 하고 에디터에서 지정할 수 있게 함(RE A4), 이름 같고 레벨 다른 지역의 결정적 해석(RE A11).
- **FR-B6 (P0) 보강 Q&A를 에디터에 통합한다.** (R2-7=B) 질문에 대상 id·지역이 포함되고(RE B1), 답이 실제로 적용되고, 되돌리기가 동작하며(RE B2), Entity 대상 confirm·edit가 깨지지 않고(RE B3), 선택지는 고정 enum이다(RE B4). wiki 충돌 탐지가 실제 속성 키를 읽는다(RE B5). 보강 세션은 에디터 상태의 일부로 관리한다(메모리 유실 허용 — 데모 용도).
- **FR-B7 (P1) 상식 wiki 결과를 에디터에 보인다.** 빌드가 만든 WikiPrior 목록과, 각 연결·지식이 어느 prior에 근거했는지를 보인다. prior 편집은 P2.
- **FR-B8 (P0) 월드 저장·로드.** (R2-8=A) 저장 포맷 = 현 export JSON을 확장한 **World File**: `format_version`, 지역·연결·엔티티·관계·지식·스코프·WikiPrior·NPC·메타(이름·설명). 저장(다운로드·서버 저장)과 로드(업로드 → 그래프 교체)를 UI·CLI·API에서 지원한다. 로드는 LLM을 호출하지 않는다. 저장 → 로드 → 저장이 동일해야 한다(PBT-02).
- **FR-B9 (P1) 월드 목록.** 저장된 월드를 골라 열 수 있다. 지금은 world_id를 직접 입력해야 한다.
- **FR-B10 (P1) 관계(RELATED_TO)를 다시 읽는다.** 로더가 관계를 읽어 에디터·export에 포함한다(RE A5). 끊긴 관계 탐지가 실제로 동작한다.

### FR-C 플레이어 모드 (Player Mode)
- **FR-C1 (P0) 플레이어 생성·배치.** 세션을 시작할 때 플레이어(이름, 시작 지역)를 만든다. 플레이어 상태는 세션에 속하며 PostgreSQL에 저장한다.
- **FR-C2 (P0) 연결을 따라 이동한다.** 현재 지역에서 `CONNECTED_TO`로 이어진 지역으로만 이동한다. 이동 비용은 연결 가중치에 따라 커진다(가중치 낮음 = 턴 더 소모). 막힌 연결(`blocked`)은 지나갈 수 없다(가정 A-2). 구체 공식은 Functional Design에서 정한다.
- **FR-C3 (P0) 행동이 턴을 진행한다.** 이동, 대화 마침, "기다리기" 같은 행동이 턴을 소모하고, 턴이 소모될 때 기존 턴 엔진(`advance_turn`)이 돈다. GM 모드의 수동 턴 버튼도 남는다(FR-D1).
- **FR-C4 (P0) NPC와 대화한다.** (R2-2=A) 현재 지역의 NPC를 골라 자유 텍스트로 대화한다. NPC의 "아는 범위"는 **그 지역에서 알 수 있는 것**으로 제한한다: 정적 지식(direct + inherited + global) + 그 지역의 활성 세션 소문(왜곡된 문장 그대로) + NPC 자신의 설명. 범위 밖 질문에는 모른다고 하거나 소문대로 틀리게 말한다. 대화 이력은 세션 안에 저장한다. 한 대화 턴 = LLM 호출 1회(+번역 정책은 A-1).
- **FR-C5 (P0) 현재 지역 화면.** 지역 이름·설명·계층 위치, 이곳의 NPC 목록, 이곳에서 들리는 이야기(정적 지식 + 소문, 소문은 왜곡도 표시), 이동할 수 있는 연결(종류·비용). 지역은 항상 **이름**으로 보인다(RE: UUID 노출).
- **FR-C6 (P1) 플레이 로그.** 플레이어 시점의 기록(이동, 대화 요약, 들은 소문, 겪은 사건)을 타임라인과 나눠 보인다.
- **FR-C7 (P2) 캐릭터 시트.** 스탯·인벤토리·전투는 범위 밖이다(§10). 이름·시작 지역·현재 위치·턴 수만 가진다(가정 A-3).

### FR-D GM 모드 (GM Mode)
- **FR-D1 (P0) 모드 전환.** 플레이어 화면에서 GM 모드로 들어가고 나온다. GM 모드는 기존 GameMaster 기능을 유지한다: 이벤트 생성·제안·승인·해결·폐기, 지역 왜곡도, 소문 생성·재생성·지지도, 수동 턴 진행, 타임라인, 지역별 변동 알림.
- **FR-D2 (P0) 이벤트 제안이 월드를 본다.** LLM 제안 프롬프트에 지역 이름·설명·최근 사건·주요 지식을 넣는다(RE C7). `n`에 상한을 둔다(RE C8).
- **FR-D3 (P0) 지역은 이름으로 보인다.** 이벤트·타임라인·알림에서 UUID 대신 지역 이름을 쓴다.
- **FR-D4 (P1) 세계 상태 보기.** 지역별 왜곡도·소문 수·승격 수를 지도 위에 겹쳐 보인다(색·크기). "왜 그렇게 되었는가"를 관람자에게 보여 주는 화면이다.
- **FR-D5 (P1) 슬라이더 저장 방식.** 키보드·터치 변경도 저장한다(RE).

### FR-E 시뮬레이션 안정화 (Simulation Hardening)
- **FR-E1 (P0) 소문 폭주를 막는다.** (RE C1 재현) 지역·턴당 새 소문 수에 상한을 두고, 캐노니컬 원본이 매 턴 다시 씨앗이 되지 않게 하며(이미 파생된 원본 제외), 탄생 지지도 + 강화가 원본 자격 기준에 정확히 걸리지 않게 파라미터를 조정한다. 속성: "턴당 LLM 호출 ≤ 상한", "활성 소문 수는 지역당 상한 이하"(PBT-03).
- **FR-E2 (P0) 승격 소문의 면제 범위를 줄인다.** (RE C2) 승격 소문 하나가 지역 전체의 감쇠를 끄지 않는다. 되먹임 왜곡은 복원 대상에 포함하거나 상한을 둔다.
- **FR-E3 (P0) 턴 진행을 하나의 단위로 만든다.** (RE C3) 한 세션에 턴 진행이 동시에 두 번 돌지 않는다(잠금 또는 상태 검사). 저장은 가능한 한 하나의 트랜잭션으로 묶는다. LLM 호출은 저장 트랜잭션 밖에서 한다.
- **FR-E4 (P1) 이벤트 상태 기계를 닫는다.** SUGGESTED는 승인 전 해결할 수 없다(RE C5). 폐기·세션 시작·종료도 타임라인에 남긴다.
- **FR-E5 (P1) 소문 계보를 보존한다.** 재생성은 부모를 hard-delete하지 않고 비활성화한다(RE C6). 삭제 방식은 하나로 통일한다.
- **FR-E6 (P1) 세션 시작 뒤 추가된 지역도 왜곡도를 가진다.** (RE C12)
- **FR-E7 (P2) 조정값 외부화**는 FR-A7로 다룬다.

### FR-F NPC
- **FR-F1 (P0) NPC 모델.** `id, world_id, name, role, home_region_id, description(persona), traits?, provenance`. 캐노니컬 월드의 일부로 Neo4j에 저장하고(`:NPC` 노드, `LIVES_IN` 엣지), World File에 포함한다. 세션 상태(대화 이력)는 PostgreSQL에 둔다.
- **FR-F2 (P0) NPC 편집.** 에디터에서 추가·편집·삭제한다(FR-B2). 데모 월드에 NPC가 들어 있다(FR-B3).
- **FR-F3 (P1) NPC 초안 제안.** 지역을 고르면 LLM이 그 지역 지식에 맞는 NPC 초안 1~3명을 제안하고, 사용자가 받아들인다. 빌드 시 자동 생성은 하지 않는다(사용자가 정한다).
- **FR-F4 (P0) 아는 범위 계산.** "NPC가 아는 것" = `knowledge` 경계의 지역 지식(direct + inherited + global) + play 경계의 그 지역 활성 소문. 이 계산은 순수 함수로 두고, 속성 테스트로 "범위 밖 지식 id가 프롬프트 컨텍스트에 들어가지 않는다"를 검증한다(PBT-03). 기존 `SessionQueryEngine`이 이 계산의 씨앗이다.
- **FR-F5 (P1) 외부 NPC 계약 유지.** `QueryResult`(세션 지역 지식)는 API로 계속 노출한다. 외부 NPC 런타임이 붙을 수 있게 하되, 이번 사이클의 소비자는 내부 NPC 대화다.

### FR-G 로컬라이징 (Localization)
- **FR-G1 (P0) 번역 모듈을 세션 도메인에서 분리한다.** `Translation` 모델·저장·서비스를 localization 경계로 옮기고, 자체 포트를 둔다. play·world 어디서든 쓸 수 있다.
- **FR-G2 (P0) 표시 언어 정책.** 임베딩·검색 대상 텍스트(지식·엔티티·WikiPrior·소문 문장)는 **영어로 생성·저장**한다(제약 C-1). 화면에는 한국어 번역 캐시로 보이고 원문 토글을 유지한다. 캐노니컬 지식(에디터, 현재 지역 화면)도 번역 대상에 넣는다.
- **FR-G3 (P0) NPC 대화 언어.** 대화문은 임베딩하지 않으므로 표시 언어(설정, 기본 한국어)로 직접 생성한다(가정 A-1). 대화에 인용되는 지식·소문은 영어 원문을 컨텍스트로 넣고 NPC가 표시 언어로 말한다.
- **FR-G4 (P1) 번역 워밍 개선.** 중복 요청 억제, 삭제된 항목의 행 정리(RE C9). 생성 시점 워밍(쓰기 응답에도 `_ko`)은 P2.
- **FR-G5 (P1) UI 언어 통일.** 남아 있는 영어 라벨(툴바, 지역 패널, 세션 바, Approve/Discard/Resolve)을 i18n 사전으로 옮긴다.

### FR-H 데모·배포·문서 (Demo, Deployment, Docs)
- **FR-H1 (P0) 목적 문장 반영.** README 첫 줄, `pyproject` description, CLAUDE.md Project Overview, 페르소나·스토리에 §0 문장을 쓴다. README는 전면 갱신한다(RE §7의 낡은 항목 10개 제거, 새 흐름·스크린샷 자리·기동 방법).
- **FR-H2 (P0) Docker 한 번에 기동.** `service` 프로파일이 실제로 뜬다: Dockerfile에 `api/` 포함, `.dockerignore`, `requirements.txt` 정합(sqlalchemy·psycopg), `tools` 프로파일 정리(문서와 compose 일치). 관람자가 `.env` 두 값만 채우고 `docker compose --profile service up -d`로 플레이할 수 있다.
- **FR-H3 (P1) 진행 중 기능 표시.** 옮겨 두기만 한 기능(FR-I)을 README와 UI에 "진행 중"으로 표시한다.
- **FR-H4 (P1) 라이선스·메타 정합.** `pyproject` license와 `LICENSE` 파일을 맞춘다. `web` peer 의존성 충돌(plugin-react ↔ vite 8)을 해소한다.
- **FR-H5 (P2) 최소 CI.** GitHub Actions로 pytest·vitest·ruff·black·tsc를 돈다. PBT-08(seed 로깅)을 여기서 만족시킨다.

### FR-I 미완성 기능 처리 (Kept Unfinished Features)
(R2-5=X, R2-7=B) 다음 기능은 **지우지 않는다.** 새 경계로 옮기고, 에디터에 닿는 것은 이번에 완성한다.

| 기능 | 이번 사이클 | 근거 |
|---|---|---|
| 보강 Q&A | **완성** (FR-B6) | 에디터에 직접 닿음 |
| 상식 wiki 조회·근거 표시 | **완성 (표시까지)** (FR-B7) | 에디터에 닿음. prior 편집은 P2 |
| wiki 증류·연결·고증 | world 경계로 **옮김**, 동작 유지 | 빌드 흐름의 일부. 순환 구조 개선은 다음 사이클 |
| 교차 월드 prior 검색 | **옮김** + 필터 경로 결함(RE A6) 수정은 P2 | UI 없음 |
| 컨셉아트 수집 | **옮김**, 진행 중 표시 | 이미지 전송(FR-B1)이 고쳐지면 시험 가능해짐 |
| OpenSearch Knowledge·Entity 색인 | **유지** | wiki 유지 + 임베딩 정책(C-1)과 함께 감. 읽는 곳은 다음 사이클 |
| LangGraph 래퍼 | **옮김**, 진행 중 표시 | 호출되지 않지만 "앞으로 구현할 것" |

## 8. 비기능 요구사항 (Non-Functional Requirements)

- **NFR-1 회귀 없음.** 기존 오프라인 테스트(백엔드 281 + 프론트 24)는 경계 이동 뒤에도 GREEN이다. 삭제되는 기능이 없으므로 테스트도 삭제하지 않고 import 경로만 바꾼다. 의도적으로 바꾸는 동작(FR-E1·E2)은 테스트를 고치고 그 이유를 기록한다.
- **NFR-2 PBT Partial.** blocking 규칙 PBT-02/03/07/08/09. 대상: World File 저장↔로드 왕복(PBT-02), 이동 비용 단조성·범위, 턴당 소문·LLM 호출 상한, NPC 아는 범위 불변식(PBT-03), 도메인 생성기(월드·세션·NPC)는 재사용 가능한 test util로(PBT-07), hypothesis seed 로깅(PBT-08), hypothesis 유지(PBT-09). PBT-01(설계 시 속성 식별)은 advisory지만 Functional Design마다 "Testable Properties" 절을 둔다.
- **NFR-3 플레이 응답성.** 플레이어 행동(이동·화면 전환)은 LLM 없이 즉시 응답한다. 월드 전체 로드는 세션 단위로 캐시한다(지금은 질의마다 로드 — RE §G). NPC 대화와 턴 진행만 LLM을 기다린다. 긴 작업(턴 진행, 대화)은 UI에 진행 상태를 보인다.
- **NFR-4 데모가 끊기지 않는다.** §6 흐름이 새 환경에서 `.env` 두 값만으로 한 번에 돈다. 원클릭 데모 월드는 LLM 없이 로드되어, API 키 없이도 에디터와 지도는 볼 수 있다(플레이 대화·턴은 키 필요).
- **NFR-5 LLM 비용 상한.** 턴당 LLM 호출 상한(FR-E1), 빌드 시 호출 수를 리포트에 표시, 대화 1턴 = 호출 1회.
- **NFR-6 보안은 NFR로만.** 인증 없음 유지(로컬 데모). 입력 검증(업로드 크기·형식, `n` 상한), 에러 응답에 내부 정보 노출 없음, 의존성 취약점 0(npm audit). DB 포트 공개·OpenSearch 보안 해제는 로컬 전제로 두고 README에 적는다.
- **NFR-7 코드 품질.** ruff·black·tsc clean 유지. mypy 오류는 늘리지 않는다(16 → 줄이면 좋음). 중복 헬퍼(정규화 6곳, clamp 5곳)는 경계 이동 때 하나로 모은다. `SessionPanel` 같은 god component는 모드별로 나눈다.
- **NFR-8 문서 정확성.** README·CLAUDE.md·operations·web/README가 코드와 일치한다. 사이클 마지막에 RE 문서의 "낡은 항목" 목록으로 대조한다.
- **NFR-9 저장소 무결성.** 월드 로드·재빌드가 세션의 캐노니컬 참조를 끊을 수 있음을 인지하고, 월드를 교체할 때 그 월드의 세션을 닫거나 경고한다.

## 9. 제약과 가정 (Constraints & Assumptions)

**제약**
- **C-1 임베딩 텍스트는 영어.** (R2-6) 벡터화·유사도(중복 제거, 정합, wiki 조회)가 한 언어에서 일관되게 동작해야 한다. 지식·엔티티·WikiPrior·소문 문장은 영어로 생성·저장한다.
- **C-2 기존 기능은 지우지 않는다.** (R2-5) 옮기고 표시한다.
- **C-3 LLM 공급자는 OpenAI 추상화 유지.** 새 경로(NPC 대화, NPC 제안)도 `LLMProvider`를 쓴다.
- **C-4 저장소 구성 유지.** Neo4j(캐노니컬) + OpenSearch(wiki 검색) + PostgreSQL(세션·번역). 새 인프라를 더하지 않는다.

**가정 (승인 시 확인)**
- **A-1 NPC 대화는 표시 언어로 직접 생성한다.** 대화문은 임베딩하지 않으므로 번역 경로를 거치지 않는다(호출 1회). 틀리면 FR-G3을 "영어 생성 + 번역"으로 바꾼다.
- **A-2 막힌 연결(`blocked`)은 지나갈 수 없다.** 우회로가 없으면 그 지역은 도달 불가다. 틀리면 "높은 비용"으로 바꾼다.
- **A-3 플레이어는 이름·위치·턴만 가진다.** 스탯·인벤토리·전투·판정은 이번 범위 밖이다.
- **A-4 데모 월드는 지역 10~15개.** 더 크면 LLM 비용과 지도 가독성이 문제다.
- **A-5 이동 비용 공식은 Functional Design에서 정한다.** 요구는 "가중치가 낮을수록 턴을 더 쓴다"까지다.

## 13. 부록 A — 변경 (2026-09-29, Application Design 단계 피드백): 플레이어의 행적이 소문이 된다

**근거**: 사용자 피드백 "결국 플레이어의 행동이 소문으로 퍼질 수도 있기 때문에, 이 점이 기존 legacy locus와는 달라지게 됨" + AD-R9(자동 행적 + 자유 텍스트 선언, **소문 가치는 대화한 NPC가 정함**) + AD-R10(토폴로지를 따라 턴마다 왜곡되며 전파). 승인된 본문은 그대로 두고 아래를 더한다. 레거시 Locus와 갈라지는 지점: **플레이어는 보기만 하는 존재가 아니라 세계에 흔적을 남기는 존재**다.

### 기능 요구사항 추가
- **FR-C8 (P0) 행적(Deed) 기록.** 지역 도착, NPC에게 말한 내용(대화 마침 때 요약), 선언 행동의 결과가 세션 행적으로 남는다(지역·턴·목격 NPC 포함). 행적은 세션 레이어에만 있고 캐노니컬 월드를 바꾸지 않는다.
- **FR-C9 (P0) 행동 선언.** 플레이어가 자유 텍스트로 행동을 선언하면(`Declare`) LLM GM이 결과를 짧게 서술한다. 판정·스탯은 없다(A-3 유지). 결과는 행적이 되고 1턴을 소모한다.
- **FR-C10 (P0) 소문 가치는 NPC가 정한다.** 모든 행적이 소문이 되지 않는다. 플레이어가 **대화한 NPC**가 자기 성격·역할·지역 지식에 따라 그 행적을 남에게 전할지(`noteworthy`), 얼마나 열심히(`salience`), 어떤 시각으로(`slant`), 어떤 문장으로(`retelling`) 정한다. 이것이 행적의 속성(`DeedAppraisal`)이다. NPC가 전하기로 한 행적만 소문의 씨앗이 된다.
- **FR-E7 (P0) 세션 기원 소문 전파.** NPC가 전하기로 한 행적은 그 NPC의 지역에서 소문으로 태어나고, 턴마다 연결 가중치(최대 곱 경로)를 따라 이웃 지역으로 퍼진다. 도달 가중치 `w`가 기준 이상이면 그 지역에 `1 − w`만큼 더 왜곡된 소문이 생긴다(기존 왜곡 체인 재사용). 퍼진 소문은 지지도·가지치기·승격 규칙을 그대로 따른다. 전파에도 지역당 상한과 턴 LLM 예산이 걸린다(FR-E1). **캐노니컬 기원 소문은 전파하지 않는다**(hearsay 계산이 이미 지역 사이를 잇는다).
- **FR-D6 (P1) GM 행적 관리.** GM 모드에서 행적·판단·전파 경로를 보고, 행적을 취소(void)할 수 있다. 취소된 행적에서 난 소문은 비활성화된다.
- **FR-D2 보강.** 사건 제안 컨텍스트에 최근 행적을 넣는다(플레이어의 일이 사건을 낳을 수 있다).
- **FR-F4 보강.** NPC 아는 범위에 "자기가 판단한 행적"과 지역 활성 소문(행적 기원 포함)이 들어간다.
- **NFR-5 보강.** 대화 마침 판단 1회, 선언 서술 1회, 전파 소문 생성 1회/지역 — 모두 턴 예산에 포함한다.

### 용어 추가 (§4)
| 용어 | 뜻 |
|---|---|
| Deed (행적) | 플레이어가 세션에서 한 일의 기록. 종류: `arrival`, `statement`, `declared_action` |
| DeedAppraisal (판단) | 대화한 NPC가 행적에 내린 소문 가치: noteworthy · salience · slant · retelling |
| session-origin rumor (세션 기원 소문) | 캐노니컬에 없는 내용에서 난 소문(`origin_kind = deed`). 토폴로지를 따라 전파된다 |

### 가정 추가 (§9)
- **A-6 대화하지 않은 행적은 소문이 되지 않는다.** 조용히 지나가면 흔적이 없다. 선언 행동도 그 지역에서 대화한 NPC가 판단할 때만 소문이 된다.
- **A-7 선언 행동은 판정 없이 서술만.** 성공·실패·규모는 LLM 서술에 맡기고, 과하면 GM 모드에서 취소한다.
