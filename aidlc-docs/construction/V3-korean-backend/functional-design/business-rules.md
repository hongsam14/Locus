# V3 한국어 표시 백엔드 — Business Rules

**원하시는 것**: Purpose Restructure 주기에서 넘긴 일을 처리해 솔로 TRPG를 다듬는 것. 이번 주기는 새 TRPG·판타지 디자인으로 화면 다시 만들기, 결과가 틀리는 결함 고치기, 시한 있는 부채 정리다.
**지금 하는 것**: V3 Functional Design. 키 없이 연 데모가 한국어로 보이게 하는 규칙과, 각 규칙을 확인하는 방법을 정한다.

표기:
- **검증**은 그 규칙을 지키는지 보는 방법이다.
- **테스트**는 pytest(오프라인, 포트는 가짜)이고, **검사**는 CI 이미지 잡의 `check_packaged()`다.
- TP 번호는 끝의 테스트 계획을 가리킨다.

## 테스트 계획 (TP-V3-*)

모두 오프라인이다. 번역 저장소는 `InMemoryTranslationRepository`, 그래프·검색은 지금의 가짜를 쓴다. PBT는 hypothesis(백엔드의 지금 도구)로 한다.

| ID | 무엇을 | 방법 |
|---|---|---|
| TP-V3-1 | 번역 파일 왕복 | PBT(PBT-02). 임의의 `TranslationFile`(한글·이모지·공백 섞인 원문, 빈 목록 포함)에서 `parse(to_json(f)) == f`와 `to_json(parse(j)) == j`(정규화 뒤)를 본다. 다른 `format`·`version`은 `ValueError`다 |
| TP-V3-2 | 해시 규칙 | 단위 테스트 네 가지다. (1) 앞뒤 공백만 다른 원문은 같은 해시다. (2) 한 글자라도 다르면 시딩이 `stale`로 버리고 `enrich`가 원문을 보인다. (3) 빈 원문은 건너뛴다. (4) shared로 옮긴 `source_hash`가 옛 값과 같다(고정 예) |
| TP-V3-3 | 재매핑 | PBT 하나와 예 하나다. **PBT**: 임의의 World File 일부와 번역 항목을 만든다. 재매핑한 항목 id는 언제나 `remap_ids(file)`의 id이거나 대상 월드 id다. 파일 밖 id는 그대로다. **예**: Emberleaf를 `w2`로 불러오면 123개 모두 시딩되고 `unknown`은 0이다 |
| TP-V3-4 | 검사 | BR-V3-08의 (a)~(h), BR-V3-11, BR-V3-12를 하나씩 만든 매니페스트 폴더(tmp)로 확인한다. 문제 문장에 데모 이름·언어·대상이 있다. 출고 패키지의 `check_packaged()`는 `[]`다. NPC 역할 번역에는 마침표가 없다 |
