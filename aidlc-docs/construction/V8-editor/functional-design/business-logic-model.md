# V8 에디터 화면 — Business Logic Model

**원하시는 것**: Purpose Restructure 주기에서 넘긴 일을 처리해 솔로 TRPG를 다듬는 것. 이번 주기에는 세 가지를 한다.
- 새 TRPG·판타지 디자인으로 화면을 다시 만든다.
- 결과가 틀리는 결함을 고친다.
- 시한이 있는 부채를 정리한다.

**지금 하는 것**: V8 Functional Design. 이 문서는 에디터의 읽기·쓰기 흐름을 정한다.
- 늦은 답, 지역 추가와 선택, 지도 도구, 쓰기 뒤 다시 읽기, 보강 답, 빌드·불러오기, 플레이 시작, 오류 문장을 다룬다.
- 배치와 컴포넌트는 `frontend-components.md`, 규칙과 시험은 `business-rules.md`에 있다.

서버는 바뀌지 않는다. 모든 흐름은 지금 API를 쓴다.

## 1. 월드 읽기

1. 들어오면 `useResource(["world", worldId], exportWorld)`로 월드를 읽는다.
   - 읽는 동안: 지도 자리는 로딩 판, 패널은 로딩 표시다. 빈 상태 문장은 보이지 않는다(FR-S5).
   - 404: "아직 이 월드가 없어요" + [자료로 만들기]. 지도 도구·인스펙터·[이 월드로 플레이]가 꺼진다(지금 S21).
   - 그 밖의 실패: `InlineError` + [다시 시도]. [다시 시도]는 월드와 열린 세션 수를 함께 다시 읽는다.
2. 열린 세션 수는 `listWorlds`에서 이 월드의 `open_sessions`만 읽는다(지금과 같음).
   - 들어올 때, 그리고 불러오기·빌드 뒤에 읽는다. 편집마다 읽지 않는다(U3 리뷰 C1). 플레이 시작은 화면을 떠나므로 다시 읽지 않는다(설계 리뷰 01 R-11).
   - 실패하면 수를 숨긴다. 머리의 다른 부분은 그대로다.
3. 월드 id가 바뀌면(다른 월드로 이동) 아래 4의 표에서 "월드 id 바뀜" 칸대로 비운다. 옛 월드의 늦은 답은 그리지 않는다(`useResource` 키).
4. **월드가 바뀌는 일마다 비우는 것**(설계 리뷰 01 R-04). 불러오기와 빌드는 월드를 교체하고 지역을 없앨 수 있다. 셋은 같은 규칙을 따른다.

| 상태 | 월드 id 바뀜 | 불러오기 성공(`replaced`) | 빌드 성공(`replaced`) | 편집 |
|---|---|---|---|---|
| `selected` | 비움 | 새 월드에 없으면 비움 | 새 월드에 없으면 비움 | 지운 지역이면 비움 |
| `pendingSelect` | 비움 | 비움 | 비움 | § 3 |
| `connection` | 비움 | 비움 | 비움 | 지운 연결이면 비움 |
| `augRunId`, `augDrafts` | 비움 | 비움 | 비움 | 그대로 |
| `unscopedPick` | 비움 | 비움 | 비움 | 정한 지식만 비움 |
| `moved`(끌기 덮개, § 4) | 비움 | 비움 | 비움 | § 4 |
| `inspectorOpen`(펼침) | 그대로 | 그대로 | 그대로 | 그대로 |
| 지도 그림 | 비움 | 그대로 | 그대로 | 그대로 |

   - 교체를 모르고 쓴 보강 run(다른 탭·CLI가 교체함)이 답·되돌리기에 404를 받으면 "질문의 대상이 월드에 없어요. 보강을 새로 시작해 보세요" + [새로 시작]을 보인다. 400은 § 6의 일반 문장이다.

## 2. 늦은 답

- 월드 읽기는 `useResource`의 키(월드 id)로 늦은 답을 버린다.
- 인스펙터의 지역 읽기(`getEditorRegion`)는 키 `(worldId, regionId, lang)`를 쓴다. 지역을 빨리 바꿔도 옛 지역의 답이 새 지역을 덮지 않는다(지금 S31을 지킴).
- 쓰기 뒤의 다시 읽기는 키를 바꾸지 않고 `reload()`로 한다(지금의 `rev` 키 방식을 쓰지 않음, 설계 리뷰 01 R-13). 그래서 상태가 "loading"으로 돌아가 화면을 비우는 일이 없다.
- **로딩 판과 로딩 표시는 `data`가 아직 없을 때만** 보인다. 다시 읽는 동안에는 이전 내용을 그대로 그린다(BR-V8-25).
- 범위 없는 지식·사전 읽기는 `(worldId)` 키를 쓰고, 쓰기 뒤에는 `reload()`한다.
- 보강 run 읽기(`getRun`)는 run id 키를 쓴다. 404면 "이 보강은 끝났어요" + [새로 시작](지금 `augment-lost`).

## 3. 지역 추가와 선택 (UX-25)

지금은 만든 뒤 바로 `selected`를 정한다. 그런데 월드를 다시 읽기 전의 렌더가 "없는 지역 선택 지우기"를 돌려 선택이 사라진다.

바뀐 흐름
1. [지역 추가] 대화상자 저장 → `createRegion`.
2. 성공하면 `pendingSelect = made.id`, 탭은 [지역]으로 둔다.
3. 월드를 다시 읽는다.
4. 다시 읽은 월드에 그 id가 있으면 `selected = pendingSelect`, `pendingSelect = null`이다. 인스펙터가 열린다. 섹션의 펼침은 사용자가 정해 둔 대로다(새 지역이라고 펼침을 바꾸지 않음, 설계 리뷰 01 R-08).
5. "없는 지역 선택 지우기"는 `pendingSelect`가 비어 있을 때만 돈다. 그리고 다시 읽은 월드 기준으로만 돈다.
6. **`pendingSelect`가 풀리는 때**(설계 리뷰 01 R-03). 페이지는 월드 답이 올 때마다 1씩 느는 `worldGen`을 쥔다. `pendingSelect = {id, gen}`의 `gen`은 만들기 성공 때의 `worldGen`이다.

| 일 | 결과 |
|---|---|
| `worldGen > gen`인 월드가 그 id를 담음 | `selected = id`, 풀림 |
| `worldGen > gen`인 월드가 그 id를 담지 않음(만들기 응답보다 먼저 시작한 읽기는 `gen` 비교로 건너뜀) | 풀림. 선택하지 않고, 지역 추가 자리에 "새 지역을 찾지 못했어요" 문장 |
| 월드 다시 읽기 실패 | 풀림. 월드 오류 문장이 보인다 |
| 월드 id 바뀜, 불러오기·빌드 성공 | 풀림(§ 1의 4 표) |
| 사용자가 그 사이 지도나 지역 고르기로 다른 지역을 고름 | 풀림. 사용자의 선택이 이긴다 |

- 만들기 응답과 다시 읽기의 순서는 `gen`으로 가른다. 만들기 성공 뒤에 시작한 읽기만 판정에 쓴다.

- 불러오기·빌드가 지역을 없애면 선택을 지운다(지금 규칙을 지킴).
- 지도에서 지역을 누르면 `selected`를 바꾸고, 연결 선택을 지우고, 탭을 [지역]으로 연다. 좁은 폭에서는 패널 머리로 스크롤한다. 스크롤은 `element.scrollIntoView?.()`로 부른다(jsdom에는 없음, 설계 리뷰 01 R-14).
- 지도에서 선을 누르면 연결을 고르고, 그 출발 지역을 고르고, [연결] 섹션을 펼친다.
- 지역 고르기(`Select`)는 지도 누름과 같은 일을 한다.

## 4. 지도 도구

| 도구 | 동작 | 쓰기 |
|---|---|---|
| 선택·이동 | 누르면 고름. 4px 넘게 끌면 옮김 | 끌기 한 번 = `updateRegion` 한 번. 월드를 다시 읽지 않는다. 인스펙터는 `reload()`로 자기 지역을 다시 읽어, 저장할 때 옛 자리를 되돌려 쓰지 않는다(지금 C1, U3 #1) |
| 지역 추가 | 빈 곳 누름 → 대화상자(누른 자리) | `createRegion` → § 3 |
| 연결 긋기 | 첫 지역 → 둘째 지역 → 대화상자 | 같은 쌍·종류가 있으면 그 연결을 고친다. 근거·사전·출처는 지키고 가중만 바꾼다(U3 #15). 없으면 새로 만든다. 끝나면 월드를 다시 읽는다 |

- **새 연결 폼의 가중**(설계 리뷰 01 R-12)
  - 폼의 `CommitRange`는 값만 정한다. 쓰기는 [저장]이 한다. `onDraft`와 `onCommit` 모두 폼의 값을 바꾼다.
  - 처음 값은 같은 쌍·종류의 연결이 있으면 그 가중, 없으면 0.6이다(지금 기본값).
  - 종류를 바꾸면 그 종류의 기존 가중으로, 없으면 0.6으로 다시 맞춘다.
  - 건드리지 않고 [저장]하면 그 처음 값이 저장된다.
- **목록의 가중**: `CommitRange`를 놓을 때(`onCommit`) 그 연결을 한 번 저장한다. 끄는 동안(`onDraft`)에는 저장하지 않고, 라벨만 따라간다.

- **끌기의 새 자리**(설계 리뷰 01 R-02). `useResource`는 값을 바꾸는 길이 없으므로, 페이지가 덮개 `moved: {[regionId]: {x, y}}`를 쥔다. 지도에 넘기는 지역은 월드의 지역에 이 덮개를 씌운 것이다.
  - 끌기를 놓으면 덮개에 새 자리를 넣고 `updateRegion`을 보낸다.
  - 덮개 칸은 월드 답의 그 지역 자리가 덮개와 같아지면 지운다. 서버는 보낸 수를 그대로 저장하므로 다시 읽은 월드에서 같아진다.
  - 저장이 실패하면 그 칸을 지우고 월드를 다시 읽는다. 지도 머리 아래에 `InlineError`가 보인다(문장만 지금과 다름).
  - 월드가 교체되면 덮개를 비운다(§ 1의 4 표).
- **끌기는 `useAction`을 쓰지 않는다.** 끌기마다 따로 저장을 보낸다. 겹친 끌기를 버리거나 줄 세우지 않는다. 같은 지역의 겹친 저장은 서버에서 나중 것이 이긴다. 덮개는 마지막 자리를 쥔다. 지금 코드는 끌기 동안 `busy`를 켜지만 대기열은 없다. 앞의 "지금과 같음"은 틀린 말이었다.
- 끌기 저장 중에도 도구 단추와 끌기는 켜져 있다. 대화상자를 거치는 쓰기(지역 추가, 연결)만 `useAction`의 `busy`로 꺼진다.
- 끌기가 취소되면(포인터 취소, 포인터 캡처를 잃음) 저장하지 않는다(지금 S23).

## 5. 쓰기와 다시 읽기

모든 쓰기 단추는 `useAction`을 쓴다. 요청 중에는 꺼지고, 같은 쓰기가 두 번 나가지 않는다.
- 실패는 그 자리의 `InlineError`로 보인다.
- 성공 알림은 아래 표의 "알림" 칸을 따른다.

| 쓰기 | 다시 읽기 | 알림 |
|---|---|---|
| 지역 기본 정보 저장 | 월드 + 인스펙터(`reload()`) | 없음(저장 단추가 "저장했어요"로 1초) |
| 지역 끌기 | 인스펙터만(`reload()`), 덮개(§ 4) | 없음 |
| 지역 추가 | 월드, 그 뒤 선택(§ 3) | 없음 |
| 지역 지우기 | 월드. 선택을 지운다 | "○○ 지역을 지웠어요"(지금 알림) |
| 연결 만들기·고치기·가중·지우기 | 월드 + 인스펙터 | 없음 |
| 지식 더하기·고치기·지우기·범위 고치기 | 월드 + 인스펙터 + 범위 없는 지식 | 없음 |
| NPC 더하기·고치기·지우기·제안 받기 | 인스펙터 | 없음 |
| 범위 없는 지식에 지역 정하기 | 월드 + 범위 없는 지식 | 없음 |
| 보강 답·되돌리기·다시 보기 | run(응답에 담김) + 월드 + 인스펙터 | 없음 |
| 사전 지우기 | 사전 목록 + 월드 | 없음 |
| World File 불러오기 | 월드 + 열린 세션 수. § 1의 4 표대로 비움 | "불러왔어요"(닫은 세션이 있으면 수를 붙임) |
| 빌드 | 월드 + 열린 세션 수. 교체면 § 1의 4 표대로 비움 | 리포트가 대화상자에 남는다. 대화상자를 닫으면 "빌드 끝" 알림 |
| 플레이 시작 | 없음(화면을 떠남) | 없음 |

- 월드 다시 읽기는 화면을 비우지 않는다. 읽는 동안에도 지금 월드를 그대로 두고, 답이 오면 바꾼다(`useResource.reload`).

## 6. 보강 답

1. 탭을 처음 열 때 run id가 없으면 [보강 시작]을 보인다. 있으면 그 run을 읽는다(지금 `runId`/`onRunId` 넘김을 지킴).
2. 카드에 쳐 둔 답은 페이지의 `augDrafts`에 둔다. 열쇠는 **`issue_key`**다(지금 코드와 같음, 설계 리뷰 01 R-01). 다시 탐지하면 질문 id가 모두 새로 나므로 질문 id로 두면 다른 카드의 입력이 사라진다(지금 S28이 지킴).
   - 탭을 바꾸거나 지도를 눌러도 남는다.
   - 답을 보내 성공하면 그 카드의 `issue_key` 초안을 지운다. 지우는 일은 페이지의 답 보내기 함수가 응답을 받은 자리에서 한다. 패널이 그 사이 내려가도(탭을 바꿈) 페이지가 하므로 빠지지 않는다. `useAction`의 `onDone`에 맡기지 않는다(내려간 뒤에는 부르지 않음).
   - 다른 카드의 초안은 그대로다(지금 S28).
   - 응답의 run에 더는 없는 `issue_key`의 초안은 그대로 둔다. 다시 나오면 다시 보인다.
3. 답을 보내면(`answer`) 응답의 run으로 화면을 바꾸고, 월드와 인스펙터를 다시 읽는다.
4. 표기
   - 상태: `augmentationStatus` 라벨에 "답한 질문 N개"를 붙인다. 멈춤·수렴은 문장으로 보인다.
   - 질문 카드: 대상 종류 라벨 + 대상 이름 + 문제 종류 라벨이다. 끊긴 참조 질문은 "어디를 가리켜야 하나요: ○○(종류)"로 보인다.
   - 변경 기록: `description`의 `type:action`을 `augmentationIssue`·`augmentationAction` 라벨로 바꾼다. 모르는 값은 "변경"이다.
   - 무시한 질문과 이대로 둔 질문은 `Issue.key`에서 이름을 찾는다(설계 리뷰 01 R-07). 열쇠는 `type:target_kind:ids:field:broken`이다. `ids`는 대상 id들을 `|`로 이은 것이고, 지역 id에도 `|`가 들 수 있다.
     - 먼저 `:`로 앞의 둘(`type`, `target_kind`)과 뒤의 둘(`field`, `broken`)을 떼고, 가운데 남은 것을 `ids`로 둔다(가운데에 `:`가 있어도 됨).
     - `target_kind`별로 이름을 찾는다.

| `target_kind` | 이름 |
|---|---|
| `region` | 그 id의 지역 이름 |
| `knowledge` | 그 id의 지식 제목 |
| `entity` | 그 id의 엔티티 이름 |
| `connection` | 월드 연결 가운데 "작은 id\|큰 id\|종류"가 `ids`와 같은 것의 두 지역 이름 + 종류 라벨(예: "솔트웨이크 – 아이언크래그 · 길"). 못 찾으면 이름 없음 |

     - 끊긴 참조(`field`가 있음)는 이름 뒤에 칸 이름의 라벨을 붙인다. 예: "물고기 · 다룬 대상"(`about_entity_ids`).
     - 어느 단계에서든 못 찾으면 "이름 없는 항목"이다. 열쇠 글자는 화면에 보이지 않는다.
   - 질문 카드의 칸 이름(`target.field`, 지금 `<code>about_entity_ids</code>`)도 사전 라벨로 보인다. 칸 라벨: `parent_id` 상위 지역, `located_in` 있는 곳, `wiki_prior_ref` 근거 사전, `derived_from_prior_ids` 바탕 사전, `about_entity_ids` 다룬 대상.
5. 되돌리기는 지금처럼 최신 것만 켜진다. 되돌리면 V7대로 이대로 둔 질문이 다시 나온다(서버가 함).
6. 오류는 `describeError` 문장이다. 보강의 400 `invalid_request`는 원인이 여럿이다(무변경 답, 빈 문장, 참조 없음, 지역 없음, 이 질문에 없는 행동, `apply.py`). 코드만으로는 가를 수 없다. 그래서 일반 문장 "이 답으로는 저장할 수 없어요 — 입력을 확인해 보세요"를 보이고, 서버 원문은 접어 둔다(설계 리뷰 01 R-06).

## 7. 빌드와 불러오기

### 7.1 불러오기 (`FileActions`)
1. [파일 ▾] → [불러오기] → 파일 고르기. 고른 뒤 input 값을 비운다(같은 파일을 다시 고를 수 있게, 지금 동작).
   - 숨은 파일 `<input>`(`file-input`)은 펼침 줄 **밖**, `EditorHeader`에 늘 마운트돼 있다. [불러오기]는 그 input을 누른다. 펼침 줄이 닫혀도 파일 고르기의 `change`가 온다(설계 리뷰 01 R-09).
   - 펼침 줄은 Esc, 바깥 누름, 줄 안의 동작 하나가 시작될 때 닫힌다. 닫히면 초점이 [파일 ▾]로 돌아간다. 동작이 대화상자를 열면 대화상자가 초점을 가져가고, 대화상자가 닫힐 때 [파일 ▾]로 돌려준다.
   - 파일 오류(`file-error`)는 펼침 줄이 아니라 머리 아래에 보인다. 줄이 닫혀도 남는다.
   - 좁은 폭에서는 머리 줄이 감긴다: 이름 → 수 → [파일 ▾] [이 월드로 플레이] → 열린 세션 수.
2. 교체 확인(`ConfirmDialog`).
3. 열린 세션이 있으면 닫기 확인을 한 번 더 받는다(지금 두 단계, 409 `sessions_open` → `confirm=true`).
4. 결과
   - 성공: 알림을 보이고, 월드와 열린 세션 수를 다시 읽는다.
   - `ok=false` 리포트(중복 id, 백업 실패): 대화상자 안에 단계 라벨과 문장을 보인다. 월드는 그대로다.

### 7.2 빌드 (`BuildPanel`)
- 지금 흐름을 지킨다: 파일, 409 확인, LLM 꺼짐, 닫았다 열기.
- 리포트는 `frontend-components.md` § 4.6이다.
  - [범위 없는 지식 N 보기]는 대화상자를 닫고 [범위 없는 지식] 탭을 연다(UX-22).
  - 이어 붙인 수를 보인다.
  - 경고는 단계 라벨로 묶는다. 서버 문장은 펼침 안에 둔다.
- 단계 `sessions`의 경고("session … was busy/mid-turn and could not be closed")는 "열린 세션 N개를 닫지 못했어요. 다음 턴에서 멈춰요"로 보인다(V6 이월, 서버 BR-U4-11).

## 8. 플레이 시작 (Q2 = A)

1. [이 월드로 플레이] → `NewSessionForm`을 연다(홈과 같은 폼, 바꾸지 않음). 시작 지역은 폼의 평면 목록("이름 · 단계")이다(설계 리뷰 01 R-11).
   - 에디터가 넘기는 props: `open`, `worldId`, `regions`(월드의 지역), `busy`(`useAction`), `error`(`useAction`의 `DescribedError`), `onSubmit`, `onCancel`. `nameOf`는 넘기지 않는다(에디터는 원문 이름을 쓴다).
2. 시작 → `startSession(worldId, {name, start_region_id})` → `/play/:sessionId`로 간다.
3. 실패하면 폼 안에 `describeError` 문장을 보이고 폼은 열린 채다. 페이지가 이미 떠났으면 이동하지 않는다(`useMounted`).
4. 월드가 없거나 지역이 0개면 단추가 꺼지고, 이유를 보조 글로 보인다.

## 9. 오류 문장 (FR-D9)

- 모든 오류는 `describeError(e)` 문장이고, 원문은 접는다. `String(e)` 21곳을 없앤다.
- 에디터에서 자주 나는 것

| 경우 | 문장 |
|---|---|
| 404 월드·지역·지식 없음 | "찾을 수 없어요 — 다른 곳에서 지워졌을 수 있어요"(+[다시 시도]) |
| 409 `sessions_open` | 닫기 확인으로 이어짐(문장 아님) |
| 409 `region_in_use` | "이 지역에 플레이어가 있는 세션이 있어요: ○개"(지금 S05, 내부 id는 보이지 않음) |
| 409 `world_exists` | 교체 확인으로 이어짐 |
| 400 `invalid_request` | 서버 문장의 뜻을 사람 말로. 보강 무변경 답은 § 6 |
| 503 LLM 필요 | "이 일에는 LLM이 필요해요"(지금 `llm.required`) |
| 네트워크 | 지금 `describeError`의 네트워크 문장 |
