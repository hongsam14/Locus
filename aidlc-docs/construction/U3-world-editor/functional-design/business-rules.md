# U3 월드 에디터 — Business Rules

**원하시는 것**: 세계관 자료로 월드를 만들고, 그 안에서 소문과 사건이 지형을 따라 퍼지며 지역마다 NPC가 다르게 아는 것을 직접 겪는 솔로 TRPG.
**지금 하는 것**: U3 기능 설계 중 규칙입니다. 다음 규칙을 정하고, 규칙마다 확인할 속성(TP)과 예제(EX)를 붙입니다.
- 편집·삭제
- 열린 세션
- NPC 초안
- 보강 Q&A
- wiki
- 화면

번호는 `BR-U3-n`이고 안정적이다. 근거 열의 Q는 FD-U3 답, A3은 플랜 가정, 이탈은 domain-entities §8이다.

## 1. 저장과 편집 공통
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U3-1 | 에디터의 노드 쓰기는 **속성 교체**다. 비운 필드(부모·위치·설명·주제)는 저장소에서도 사라진다. 빌드·불러오기의 병합 쓰기는 그대로다 | A3-1 |
| BR-U3-2 | 검색 문서가 있는 종류(지식·NPC·엔티티·prior)는 같은 연산에서 다시 색인하거나 지운다. 그래프에서 지운 노드의 검색 문서는 남지 않는다 | A3-4, B8 |
| BR-U3-3 | 지식을 지우는 경로는 그 지식의 번역 캐시도 지운다(라우터, U5 `purge_translations`). NPC 글은 번역하지 않으므로 정리할 것이 없다 | A3-4, 검토 01 R-02 |
| BR-U3-4 | 쓰기마다 캐시를 무효화하고 `WorldMeta.updated_at`을 고친다 | U2 그대로 |
| BR-U3-5 | 경로의 `world_id`·id와 본문이 다르면 400이다 | A3-13 |
| BR-U3-6 | 참조하는 노드(부모 지역, NPC의 지역, 스코프의 지역, 연결의 두 지역)는 그 월드에 있어야 한다. 없으면 404다 | US-2.2·2.3·2.4 |

## 2. 지역
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U3-7 | 부모는 0개 또는 1개다. 자기 자신이나 자기 자손을 부모로 정하면 400이다. 부모가 바뀌면 `CONTAINS`도 바뀐다 | US-2.2 첫째, BR-16(U2) |
| BR-U3-8 | 지역 삭제(Q1=A)는 이 순서로 쓴다. 중간에 끊겨도 끊긴 참조가 남지 않게 하기 위해서다. ① 자식을 지운 지역의 부모 밑으로 옮긴다 ② 엔티티의 `located_in`을 비운다 ③ 이 지역으로 가는 스코프를 지운다(지식은 남는다) ④ NPC를 지운다 ⑤ 연결 두 방향을 지운다 ⑥ 지역 노드를 지운다. 〔Step 1.3 정정〕 각 단계 안에서는 재시도 계획의 선별 기준이 되는 쓰기를 마지막에 한다(① 새 `CONTAINS` → `parent_id` → 옛 `CONTAINS`, ② `LOCATED_IN` → `located_in`, ④ 검색 문서 → NPC 노드). 같은 삭제를 다시 부르면 끝까지 간다(BLM §1.3 5) | Q1=A, NFR 검토 R-01 |
| BR-U3-9 | 지역 삭제 뒤 지식은 하나도 사라지지 않는다. 이 지역에만 붙어 있던 지식은 "스코프 없음"이 된다. 확인 대화와 삭제 보고는 옮겨질 자식, 지워질 연결·NPC, 스코프 없음이 될 지식, 스코프만 빠질 지식, 위치가 비워질 엔티티의 수와 이름을 보인다 | Q1=A, US-2.2 넷째 |

## 3. 연결
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U3-10 | 연결은 늘 두 방향 한 쌍이다(a→b, b→a). 같은 종류·가중치·근거를 갖는다. 저장은 같은 키의 옛 쌍을 지운 뒤 새 쌍을 만든다. 삭제는 두 방향을 함께 지운다 | A3-3, US-2.2 둘째 |
| BR-U3-11 | 연결의 키는 두 지역 + 종류다. 같은 두 지역 사이에 종류가 다른 연결은 따로 있을 수 있다. 자기 자신과의 연결은 400이다. 가중치는 [0,1]이다. 종류 바꾸기는 한 연산이고 가중치·근거·prior 참조·출처를 옮긴다. 새 종류의 쌍이 이미 있으면 400이다 | edge identity(U2), 검토 01 R-09 |

## 4. 지식과 스코프
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U3-12 | "지식 추가"는 그 지역에 DIRECT 스코프 하나로 붙는다. 지식 편집은 스코프를 유지한다 | US-2.3 첫째·셋째 |
| BR-U3-13 | 스코프 지정은 DIRECT 스코프 목록 전체를 바꾼다. 빈 목록이면 "스코프 없음"이 된다. INHERITED·GLOBAL은 계산값이라 저장하지 않는다 | US-2.3 둘째 |
| BR-U3-14 | "스코프 없음" 목록은 전역이 아니고 SCOPED_TO가 없는 지식 전부다. 빌드가 못 찾은 것과 삭제가 남긴 것이 모두 들어간다. 에디터에서 지역을 골라 스코프를 지정할 수 있다 | US-2.3 둘째, RE A4 |

## 5. 열린 세션 (Q2=A)
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U3-15 | 열린 세션이 있어도 편집은 된다. 에디터는 "열린 세션 N개" 띠를 보인다 | Q2=A |
| BR-U3-16 | 열린 세션의 플레이어가 서 있는 지역은 지울 수 없다. 409와 그 세션 id 목록을 준다. 확인 대화는 미리 "지울 수 없음"을 보인다. 삭제는 그 월드의 열린 세션 GM 리스를 모두 쥔 채 확인하고 지운다. 그래서 그 사이 이동이 끼지 않고, 턴이 돌고 있는 세션이 있으면 409다 | Q2=A, 검토 01 R-09 |
| BR-U3-17 | 세션에 이미 있는 소문·사건·행적·대화는 캐노니컬 편집을 따라 바뀌지 않는다. 지운 NPC와의 대화 기록은 세션에 남고, 플레이 화면의 NPC 목록에서는 빠진다 | Q2=A, U5·U6 |

## 6. NPC
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U3-18 | NPC는 한 지역에 산다(`home_region_id`, `LIVES_IN` 하나). 지역을 바꾸면 `LIVES_IN`도 바뀐다 | US-2.4, FR-F1 |
| BR-U3-19 | NPC 삭제는 확인을 거친다(화면). 노드·`LIVES_IN`·검색 문서를 지운다 | US-2.4 둘째 |
| BR-U3-20 | NPC 초안은 LLM 호출 1회로 0~3명이다. 입력은 그 지역의 이름·계층·설명, 직접 지식 상위 8개, 이미 있는 NPC 이름이다. 저장하지 않는다. 받아들인 하나만 저장한다 | US-2.5, A3-5 |
| BR-U3-21 | 초안 필드는 상한으로 자른다: 이름 60, 역할 60, 설명 500, traits 5개 × 30. LLM이 실패하면 빈 목록과 `failed=true`다(오류 아님). LLM이 없으면 503이다 | US-2.5 셋째 |

## 7. 보강 Q&A (Q3=A)
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U3-22 | 탐지기는 여섯이다: gap, low_confidence, wiki_conflict, orphan, dangling, unscoped. wiki_conflict는 지역 `attributes.terrain_kind`를 읽는다 | Q3=A, B5 |
| BR-U3-23 | dangling은 id 속성이 그 월드에 없는 노드를 가리키는 경우다: `Region.parent_id`, `Entity.located_in`, `ConnectionEdge.wiki_prior_ref`, `Knowledge.derived_from_prior_ids`·`about_entity_ids`. 이슈 키는 유형 + 대상 + 속성이라, 한 노드의 끊긴 속성 둘은 이슈 둘이다. 〔Step 1.3 정정〕 목록 속성은 끊긴 id마다 이슈 하나다(`broken_id`, 키에 포함) | Q3=A, FR-B10, 검토 01 R-03·R-06, FD 검토 02 R-11 |
| BR-U3-24 | 질문은 대상(종류·id·이름·지역·끊긴 속성)을 싣는다. 선택지는 이슈 종류마다 고정이다(BLM §4.1). LLM은 질문 문장만 다듬고 선택지를 바꾸지 않는다 | B1, B4 |
| BR-U3-25 | 답은 질문의 대상에 적용된다(UI가 보낸 대상 id를 믿지 않는다). gap/add의 진술이 비면 400이다. Entity 대상의 confirm·edit는 엔티티를 고친다. dangling/edit의 새 참조는 `ref_id`로 받고, 그 속성에 맞는 종류의 노드여야 한다 | B1, B3, 검토 01 R-03 |
| BR-U3-26 | 답과 되돌리기는 같은 run 안에서 한다. 화면은 run을 유지한다. 답은 다음 질문을 담은 run과 "무엇이 바뀌었는지"를 돌려준다 | B2, US-2.6 둘째 |
| BR-U3-27 | 되돌리기는 그 변경이 만든 노드·엣지·검색 문서를 지우고, 지우거나 바꾼 노드·엣지·검색 문서를 되살린다. 노드는 교체로 되살린다. 한 변경은 한 번만 되돌린다(두 번째는 409). 되돌리기는 나중 것부터다. 아직 되돌리지 않은 가장 나중 변경이 아니면 409다. 〔Step 1.3 정정〕 그 변경 뒤에 run 밖에서 대상이 편집되었으면(`nodes_after`와 다름) 409이고 쓰지 않는다. 검사 순서는 404 → 이미 되돌림 → 순서 → run 밖 편집이다 | B6, 검토 01 R-08, FD 검토 02 R-08 |
| BR-U3-28 | 무시(ignore)한 이슈는 그 이슈 키로 기억해 그 run에서 다시 묻지 않는다. 한 탐지의 질문은 최대 20개, 한 run의 답은 최대 30개다(지금의 "5라운드" = 답 5개를 넓힘). 상태 전이는 BLM §4.3 표다(되돌리기 포함). 〔Step 1.3 정정〕 ignore는 기록에 쌓이지 않고 답으로는 센다. `unignore`로 풀면 다시 묻는다(stopped면 409) | 검토 01 R-03·R-04, FD 검토 02 R-08 |

## 8. wiki (Q4=A)
| 규칙 | 내용 | 근거 |
|---|---|---|
| BR-U3-29 | 빌드는 이번 빌드에서 LLM 폴백으로 만든 prior도 그 월드의 WikiPrior로 저장한다. 같은 질의는 한 prior로 묶고, 빌드당 40개까지다. 토폴로지 단계의 것은 온톨로지 전에, 온톨로지 단계의 것은 지식 저장 전에 저장한다. 연결 참조는 `증류 ∪ 이번에 만든 prior`에 없을 때만 버린다. 빌드 리포트는 `priors_created`를 보인다 | Q4=A, A9, 검토 01 R-01 |
| BR-U3-31 | wiki 탭은 prior마다 조건→효과·도메인·신뢰도와 그것을 참조하는 연결·지식을 보인다. 끊긴 참조는 "저장되지 않은 근거"로 보인다. 연결 상세는 근거 문구와 prior(또는 끊김)를 보인다 | US-2.8 |

## 9. 화면
| 규칙 | 내용 | 근거 |

| BR-U3-32 | 지우는 동작(지역·연결·지식·NPC·prior)은 모두 확인 대화를 거친다. 지역 삭제 확인은 삭제 계획(BR-U3-9)을 보인다 | US-2.2 넷째, B8 |
| BR-U3-33 | GM 화면에서는 캐노니컬 지식을 지울 수 없다(✕ 없음). 캐노니컬 편집은 에디터에서만 한다 | A3-10, B8 |
| BR-U3-34 | `/`는 월드 목록이다. 각 줄은 이름·지역 수·마지막 수정·열린 세션 수와 [편집]·[세션 시작]을 갖는다. 목록이 비면 [데모 불러오기]·[자료로 만들기]를 보인다 | US-6.4, A3-7 |
| BR-U3-35 | 빌드 화면은 메모(여럿)·구조화 지도 JSON·지도 이미지·컨셉 아트를 multipart로 보낸다. 같은 world_id가 있으면 교체 확인을, 열린 세션이 있으면 세션을 닫는다는 확인을 받는다. 리포트를 그대로 보인다 | US-2.1·2.7, A3-8 |
| BR-U3-36 | World File 저장은 내려받기다. 불러오기는 열린 세션이 있으면 "교체하고 N개를 닫는다" 확인을 받는다. 지원하지 않는 버전은 서버 문구를 보인다 | US-6.2·6.3 |
| BR-U3-37 | 에디터의 지식은 표시 언어 번역과 원문 토글을 갖는다. NPC 글은 원문이다(번역 종류 `npc` 없음, U5 A-1) | A3-9, U5, 검토 01 R-02 |

## 11. Testable Properties (PBT advisory, unit-of-work U3)
| ID | 속성 | 대상 |
|---|---|---|
| TP-U3-1 | 연결 저장 뒤 그 키의 `CONNECTED_TO`는 정확히 둘(a→b, b→a)이고 종류·가중치가 같다. 삭제 뒤 0개다. 같은 키를 두 번 저장해도 둘이다 | `upsert_connection`·`delete_connection`(가짜 그래프) |
| TP-U3-2 | 무작위 계층·연결·지식·NPC·엔티티를 가진 월드에서 아무 지역을 지운다. 그 뒤 지운 id를 가리키는 속성·엣지는 하나도 없다. 지식 수는 그대로고 자식 지역 수도 그대로다(다시 붙음). 스코프 없음 지식은 계획의 `knowledge_to_unscope`와 같다 | `delete_region` |
| TP-U3-2a 〔Step 1.3 정정〕 | 지역 삭제를 n번째 포트 쓰기 호출(graph·search, meta 갱신 포함)에서 한 번 끊는다(모든 n). 끊긴 직후 끊긴 id 속성이 0이다. 같은 삭제를 다시 부른 뒤 그래프·검색 상태는 끊김 없는 삭제와 같다 | `delete_region` + 실패 주입 가짜 |
| TP-U3-3 | 교체 쓰기 뒤 읽은 모델은 쓴 모델과 같다. 비운 필드도 비어 있다 | 그래프 가짜 + 매핑 왕복 |
| TP-U3-4 | 무작위 이슈·답 k개(1~5)를 차례로 적용한 뒤 나중 것부터 모두 되돌리면, 노드·엣지·검색 문서가 처음과 같다. 순서를 어긴 되돌리기는 거절된다. 〔Step 1.3 정정〕 열에는 ignore가 섞이고(기록 밖), run 밖 편집 하나가 들어가면 그 변경의 되돌리기는 거절되고 상태가 그대로다 | `apply_answer` + `revert` |
| TP-U3-5 | dangling 탐지 결과는 "그 월드 노드 id 집합에 없는 참조"를 직접 센 신탁과 같다 | `detect_dangling` |
| TP-U3-6 | 편집 연산 뒤에도 World File 저장 → 불러오기 → 저장이 같다(U2 PBT-02 유지) | 기존 PBT + 편집 생성기 |
