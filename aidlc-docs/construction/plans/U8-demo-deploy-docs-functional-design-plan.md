# U8 데모·배포·문서 — Functional Design 플랜 (light)

**원하시는 것**: 세계관 자료로 월드를 만들고, 그 안에서 소문과 사건이 지형을 따라 퍼지며 지역마다 NPC가 다르게 아는 것을 직접 겪는 솔로 TRPG.
**지금 하는 것**: U8의 기능 설계입니다. 처음 보는 사람이 `.env` 두 값과 명령 하나로 띄우고, 클릭 한 번으로 데모 월드를 불러와 5분 안에 플레이하게 합니다.
- 데모 월드를 TRPG 규모로 만듭니다. 막힌 길·강·길, 지역마다 다른 지식, NPC, 사건 씨앗이 들어갑니다.
- API 키가 없어도 둘러볼 수 있게 합니다.
- Docker·메타·README·진행 중 표시·CI를 실제 코드와 맞춥니다.
- 이 단계에서는 그 규칙과 콘텐츠 기준·화면을 문서로 고정합니다. Docker·compose·CI 배치는 Infrastructure Design(light)에서 정합니다.

근거

- 스토리: US-1.1~1.4, US-7.3, US-7.5, US-7.6(P2)
- 요구: FR-H1~H5, NFR-4, §0 목적 문장, 가정 A-4(지역 10~15)

  - U2: 데모는 5지역 판이고, TRPG 규모와 사건 씨앗은 U8이 맡는다(BR-U2-29).
  - U5: CLI로 월드를 교체할 때 번역을 지우지 않는다(알려진 공백).
  - U6·U7: 라이브 시나리오에 US-6.5, GM 왕복, 세계 상태 확인을 넣는다.
  - U3: `npm audit` moderate 2건은 CI에서 다룬다. operations.md의 "Web UI (U10)" 절을 고친다.

## 설계 원칙 — 데모는 데이터다 (사람의 지적, 2026-10-01)
- 코드는 데모를 매니페스트(`locus/world/demo/worlds/manifest.json`)로만 압니다. 데모 이름, 지역 id, 시작 지역, 소스 글을 코드에 상수로 두지 않습니다.
- 데모 하나는 파일 묶음입니다. World File(LLM 없이 불러오기)이 있고, 필요하면 소스(메모, 구조 지도, 지도 그림; LLM 빌드 경로)가 함께 있습니다. 매니페스트 항목이 그 파일들과 표시 정보(제목, 설명, 시작 지역)를 가리킵니다.
- 화면은 `GET /api/world/demos`로 데모를 찾아 카드로 보입니다. 데모를 하나 더하거나 바꾸는 일은 파일을 더하거나 바꾸는 것뿐이고, 코드를 고치지 않습니다.
- 테스트는 패키지에 든 데모 파일을 고정 입력으로 써도 됩니다. 이것은 "코드가 데모를 아는 것"이 아닙니다.

### FD-U8 Q1 데모 월드를 어떻게 TRPG 규모로 만드는가 (US-1.3, BR-U2-29)
배경
- 지금 데모 Aldermoor는 지역 5개이고, 연결이 막힌 길 한 쌍뿐이라 플레이어가 움직일 수 없습니다.

선택지
- A. Aldermoor 파일을 키운다 — 지금 5지역의 사실을 살려 12지역 안팎으로 늘립니다. 매니페스트 항목은 하나라 첫 화면 카드도 하나입니다. 비용: 지역 수 같은 Aldermoor 개수에 묶인 테스트 몇 개를 의도된 변경으로 고칩니다. 파일 하나라 되돌리기 쉽습니다.
- B. 새 TRPG 월드 파일을 더하고 Aldermoor는 작은 예제로 둔다 — 매니페스트 항목이 둘이 되어 첫 화면에 카드가 둘 보입니다. 기존 테스트는 그대로입니다. 비용: 두 파일을 함께 유지하고, 방문자가 둘 중 무엇을 고를지 카드 설명으로 안내해야 합니다.
- C. Aldermoor 파일을 새 월드로 바꾼다(이름까지) — 새 이야기로 시작합니다. 코드는 그대로지만, 테스트와 운영 문서·code-summary 명령의 `aldermoor`를 모두 바꿔야 합니다.

### FD-U8 Q2 사건 씨앗은 어디에 있고, 어떻게 시작되는가 (US-1.3)
배경
- 씨앗은 "이 월드에서 일어날 법한 사건" 2~3개입니다. GM이 고르면 세션에서 사건이 시작되고, 소문이 지형을 따라 퍼집니다.
