## 3. 모순·모호함 확인

- **모순 없음.** Q2=C와 Q3=A가 맞물린다. 디자인 시스템이 맨 앞에 오고, 화면은 그 뒤에 순서대로 옮긴다. CQ1~CQ4도 Q2=C의 범위 안에 있다.
- **해소한 모호함**: Q2=C는 새 디자인이 어떤 모습인지를 정하지 않았다. 그래서 CQ1~CQ4로 톤, 테마 수, 시안 형태, 좁은 화면 범위를 정했다.
- **감수한 위험(사람이 고름)**: 화면 전체를 다시 만드는데(Q2=C) 레이아웃 자동 게이트를 두지 않는다(Q7=B). 다음에 배치가 깨져도 게이트는 알려 주지 않는다. 대응은 NFR-2(사람 확인 체크리스트)와 §8 R-1이다.

## 4. 용어 (이번 주기에서 새로 쓰는 것)

| 용어 | 뜻 |

| **디자인 시안** | 새 디자인 시스템의 후보 2~3개. 각 시안은 브라우저에서 보는 HTML 페이지 하나로, 홈·플레이 화면 견본과 토큰·프리미티브 견본을 담는다. 저장소 코드가 아니라 고르기 위한 참고물이다 |

| **데모 한국어판** | 매니페스트 데모마다 곁들이는 번역 파일. 데모를 불러올 때 번역 캐시에 들어가, 키 없이도 한국어로 보이게 한다 |

## 5. 핵심 경험 흐름 (이번 주기가 바꾸는 것)

1. **처음 온 사람(휴대폰 또는 데스크톱, 키 없음)**
   - 홈에서 게임 소개 한 줄과 데모 카드를 본다. [바로 플레이]를 누르면 플레이 화면이 한국어로 열린다. 지역명, NPC, 설명, 지식, 씨앗이 모두 한국어다.
   - 플레이 화면에는 작은 지도가 있어 지금 위치와 갈 수 있는 곳이 보인다. 주 행동(기다리기·선언·이동)이 눈에 띄는 자리에 있다.
2. **플레이어**
   - 행동하면 턴 결과가 한 번 분명하게 보인다. 내부 수치(`d0.42`) 대신 말로 보인다.
   - 막힌 길은 이유가 보인다. 세션이 닫히면 그렇다고 알려 준다.
3. **GM 모드(데스크톱)**
   - 지도 옆에 패널이 붙어 있어 스크롤하며 오가지 않는다. 허브는 기능별로 나뉜다.
   - [턴 진행]을 두 번 눌러도 한 번만 진행된다. 사건 두 개를 겹쳐 해소해도 왜곡도가 정확히 돌아온다.
   - 세션 닫기는 확인을 받는다.
4. **제작자(에디터, 데스크톱)**
   - 지도 위 띠가 정돈된다. 인스펙터는 섹션별로 접힌다. 추가한 지역이 바로 선택된다.
   - 소스로 다시 빌드해도, 손으로 더한 NPC·씨앗을 잃지 않는다.

## 8. 제약, 가정, 위험

### 제약
- **C-1** 디자인 시안은 claude.ai Artifact(비공개)로 올리는 참고물이다. 저장소에 시안 코드를 두지 않는다. 고른 안의 토큰과 결정은 FD 문서에 적는다.
- **C-2** 경계 규칙을 지킨다. play는 localization과 world를 import하지 않는다. 번역은 `api/schemas.py`에서 붙인다.
- **C-3** PR #4가 아직 병합되지 않았다. 이번 주기의 커밋을 어느 브랜치에 둘지는 첫 커밋 전에 사람에게 묻는다.
- **C-4** CI 러너 전환일 2026-10-19 전에 FR-T1을 끝낸다. Workflow Planning은 이 일을 맨 앞에 둔다.
- **C-5** `--workers 1` 전제는 그대로다(프로세스 안 가드·캐시).

### 가정 (승인 때 함께 확인)
- **A-1** 데모 한국어판의 번역문은 Code Generation에서 만든다. 사람은 Build and Test에서 화면으로 확인한다. 번역 품질은 데모 한 개(Emberleaf: 지역 12, NPC 15, 지식 23, 씨앗 3) 범위다.
