# V8 에디터 화면 — Code Review 01

**원하시는 것**: Purpose Restructure 주기에서 넘긴 일을 처리해 솔로 TRPG를 다듬는 것. 이번 주기에는 세 가지를 한다.
- 새 TRPG·판타지 디자인으로 화면을 다시 만든다.
- 결과가 틀리는 결함을 고친다.
- 시한이 있는 부채를 정리한다.

**이 리뷰가 하는 것**: 승인된 V8 코드가 승인된 설계를 지키는지 결함 위주로 확인한다.
- 설계 기준: BR-V8-01~34, TP-V8-1~18, BLM § 1~9, FC § 1~7, 코드 계획 § 1.1~1.4, code-summary § 5(이탈)·§ 6(알려진 한계).
- 범위: `git diff 835d1d6..23a63de -- web`. 서버는 V8에서 바뀌지 않았다.
- 새 시험이 주장대로 잡는지도 본다.
- 코드는 고치지 않았다(리뷰 전용).

**방법**: V5~V7 리뷰와 같다.
- 네 각도를 병렬로 돌렸다.
  1. 데이터 흐름과 늦은 답(선택, 만든 지역 기다리기, 끌기 줄, 보강 run, 교체 뒤 비우기): repro 14, 빈틈 시험 6, 돌연변이 20
  2. 화면·배치·접근성(두 폭, GM 회귀, [파일 ▾], 대화상자 초점, 탭 키보드, 390 가로 스크롤): 헤드리스 Chrome 측정, 돌연변이 22
  3. 표기·오류·사전(열쇠 이름 읽기, 서버 단계 이름, 말투·짝 맞춤, 서버가 실제로 만드는 질문): repro 11, 돌연변이 21
  4. 시험의 힘: 돌연변이 79(구현 때의 58과 겹치지 않음), 순서 섞기 10회(그중 4회는 부하를 걸고)
- 각도마다 작업 사본(git worktree)을 따로 썼다.
  - 사본이 `main`에서 만들어져 넷 모두 V8 커밋(`a64a05d`)을 직접 꺼내 봤다.
  - 재현물은 세션 scratchpad의 `v8review/{data,screen,words,tests}/`에만 두었다.
  - 저장소는 바뀌지 않았다. 사본 둘이 하네스에 잠긴 채 남아 있지만 깨끗하다(`git status` 빈칸, 심볼릭 링크 없음).
- 이 세션이 상위 후보를 다시 확인했다.
  - #1: 서버 코드를 직접 읽었다.
    - `validate_references`는 깨진 참조를 버리고 `stage=import` error를 남긴다(`remap.py:166-178`).
    - 그 뒤에도 월드를 지우고 쓴다(`import_.py:73,91-118`).
    - 라우터는 세션을 닫는다(`api/routers/world.py:380`).
    - 옛 `WorldFileBar`는 불러오기마다 `onLoaded()`를 불렀다(`835d1d6`, 70행).
  - #2: 끌기 저장 본문이 마지막 월드 읽기의 지역 전체다(`useEditorWorld.ts:80-82`).
  - #3: 서버가 연결 대상 이름에 원문 종류를 넣는다(`questions.py:94`). 화면은 그대로 보인다(`AugmentQuestion.tsx:46`).
  - #6: 가중 슬라이더가 `disabled={busy}`다(`ConnectionList.tsx:84`).
  - #10: 캡처 17장을 모바일 흉내 없이 다시 쟀다. 모두 `scrollWidth = clientWidth`(390·1280)다. 데모 데이터에서는 가로 스크롤이 없다는 결론은 맞다. 그러나 처음 잰 방법으로는 그것을 알 수 없었다.
- 판정
  - **C**: 재현했거나 코드로 기제가 확정됨.
  - **P**: 기제는 실재하지만 직접 돌리지 못한 조건에 달림.
- 두 각도 이상이 같은 것을 찾은 경우는 하나로 합쳤다. 괄호 안은 각도별 번호다(D 데이터, S 화면, W 표기, T 시험).
- 심각도는 설계자·플레이어가 겪는 결과로 매겼다. 시험의 빈틈은 그 빈틈이 놓치게 할 결함의 무게로 매겼다.

## 7. 확인하고 문제없음

- **GM 회귀 없음.** `MapPanelLayout`은 옛 `GmLayout`과 같은 DOM과 class를 낸다. `gm-layout`, `gm-panel-top`, 패널 이름이 그대로이고 GM 시험도 그대로 통과한다.
- **만든 지역 선택(R-04).**
  - 읽기는 시작할 때 만들기 표식을 잡는다. 만들기보다 먼저 시작한 읽기는 판정하지 않는다.
  - 늦은 읽기, 실패, 사용자의 선택, 교체, 월드 바뀜은 모두 기다림을 푼다. #25는 오류가 이미 떠 있던 경우만이다.
- **끌기 줄(R-16).** 지역마다 저장 하나, 기다리는 마지막 자리만 보냄, `clear()` 뒤 늦은 답 버림. 지역끼리는 서로 기다리지 않는다.
- **보강(R-05·R-15).**
  - 쓰기 넷이 가드 하나를 함께 쓰고, `reset()`이 다시 연다. 404 → `getRun` 가르기는 시대를 본다.
  - 초안은 `issue_key`로 지운다. 탭이 내려간 사이 끝난 답도 지운다. 다시 탐지해도 초안이 남는다.
  - `answer()`가 클로저의 `drafts`를 읽지만 안전하다. 패널은 늘 마지막 렌더의 함수를 부른다.
- **패널 다시 읽기 등록.** 함수 Map은 마운트마다 안정적이고 내려갈 때 지운다. StrictMode에서도 맞다.
- **서버와 맞음.**
  - 빌드 단계: 서버가 내는 15개를 모두 안다. "기타"로 보이는 것이 없다.
  - 보강 enum: 문제 6, 행동 5, 상태 3, 대상 4. 연결 열쇠 `a|b|kind` 정렬도 서버와 같다.
  - `sessions` 줄의 문장과 수는 BLM § 7.2 그대로다.
- **사전.** ko·en 키 620개가 같다. 자리표시 짝이 맞고, 빠진 정적 키가 없다. 말투 규칙을 지킨다.
- **표기.** 에디터 코드에 `String(e)`·`.message`·`toFixed`가 없다. 가중·확신은 숫자와 뜻이고, 종류·단계·영역은 라벨이다.
- **접근성.** 도구 띠(toolbar, 로빙 tabindex, 화살표·Home·End, `aria-pressed`), 지도 대화상자의 초점 돌림, 범례, 지역 고르기, 섹션의 `aria-expanded`, 위험 칸 이름, 탭(이름 있는 tablist, 화살표), 대화상자의 초점 가둠과 Esc.
- **배치.** 머리 줄과 h1이 감긴다. 파일 input이 늘 있다. 머리 아래 `file-error`. 빌드 리포트·상식 근거·범위 없는 지식·파일 이름은 390에서 감긴다.
- **시험.**
  - 고친 옛 시험은 뜻을 지킨다. 예외는 #18 하나와 설계를 바꾼 run 다시 읽기(이탈 3)다.
