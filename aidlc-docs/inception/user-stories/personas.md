# Personas — Locus (Purpose Restructure, 2026-09-29)

> 이 파일은 2026-06 페르소나(P1 내러티브 디자이너 / P2 월드·레벨 디자이너 / P3 NPC 런타임)를 **대체**한다. 옛 내용은 git 이력(`ee61277` 이전)에 있다.
> 근거: `inception/requirements/purpose-restructure-requirements.md` §5, `inception/plans/purpose-restructure-story-generation-plan.md`.

**목적 문장**: Locus는 세계관 자료로 월드를 만들고, 그 월드 안에서 소문과 사건이 지형을 따라 퍼지며 지역마다 NPC가 다르게 아는 것을 직접 겪는 솔로 TRPG다.

페르소나 넷 가운데 셋(P-Builder·P-Player·P-GM)은 **같은 사람이 번갈아 쓰는 역할(hat)**이다. 한 세션 안에서 역할을 오가는 것이 정상적인 흐름이다. P-Viewer는 저장소와 데모를 보는 다른 사람이다.

---

## P-Builder — 월드 제작자

- **역할**: 세계관 자료(메모, 지도 이미지, 구조화 지도)를 올리거나 지도 위에 직접 그려 월드를 만든다. 지역·연결·지식·NPC를 다듬고 저장한다.
- **목표**: 머릿속 세계가 지형과 지식이 연결된 월드로 놓이고, 다시 열어 이어서 고칠 수 있기를 바란다.
- **주요 관심**: 자동 구성 결과가 믿을 만한가(빠진 연결, 두 벌이 된 노드가 없는가), 직접 고칠 수 있는가(토폴로지 편집), 빈틈을 채우는 도움(보강 Q&A, wiki 근거), 저장·로드가 온전한가.
- **기술 수준**: 준개발자. JSON을 읽을 수 있지만 UI에서 끝내고 싶다.
- **불만(Pain)**: 지금은 데모만 빌드되고, 연결이 조용히 사라지며, 재빌드하면 월드가 두 벌이 되고, 보강 Q&A는 답해도 반영되지 않는다.
- **성공 모습**: 메모와 지도를 올리면 초안 월드가 나오고, 지도에서 연결을 긋고 NPC를 놓은 뒤 저장한다. 다음 날 불러오면 그대로 있다.

## P-Player — 플레이어

- **역할**: 캐릭터로 월드에 들어가 지역을 오가며 NPC와 대화하고, 들리는 이야기와 소문으로 세계를 알아간다.
- **목표**: 지역마다 사람들이 다르게 아는 세계를 "겪고" 싶다. 먼 곳의 사건이 소문으로 왜곡되어 들리는 것을 직접 확인하고 싶다.
- **주요 관심**: 지금 어디에 있고 어디로 갈 수 있는가, 이 지역 NPC가 무엇을 알고 무엇을 모르는가, 내가 움직이는 동안 세계가 변하는가, 행동이 즉시 응답하는가.
- **기술 수준**: 사용자. 내부 수치(왜곡도, 지지도)를 볼 필요는 없고, 그 결과를 이야기로 겪으면 된다.
- **불만(Pain)**: 지금 화면은 GM 콘솔이라 캐릭터도, 위치도, 대화도 없다. 지역이 UUID로 보인다.
- **성공 모습**: 리버턴에서 시장 화재를 직접 듣고, 산맥 너머 하이크랙에 가면 그곳 NPC는 "불이 났다던가, 아니면 폭동이었다던가" 하고 틀리게 말한다.
- **범위 메모**: 캐릭터는 이름·위치·턴만 가진다(가정 A-3). 스탯·전투·인벤토리는 없다.
- **흔적 (변경 2026-09-29)**: 플레이어는 보기만 하는 존재가 아니다. 도착, NPC에게 한 말, 선언한 행동이 **행적**으로 남고, 대화한 NPC가 전할 만하다고 여기면 소문이 되어 지형을 따라 퍼진다. 며칠 뒤 산 너머에서 자기 일이 부풀려져 돌아오는 것을 겪는다. 이것이 레거시 Locus와 갈라지는 지점이다.

## P-GM — 게임마스터 (모드)

- **역할**: 플레이 중 GM 모드로 전환해 세계에 개입한다. 사건을 만들거나 LLM 제안을 승인하고, 지역 왜곡도와 소문 지지도를 조정하고, 턴을 직접 넘기고, 타임라인을 본다.
- **목표**: 세계가 어떻게 움직이는지(전파, 왜곡, 지지도) 들여다보고, 원하는 방향으로 밀어 주고 싶다.
- **주요 관심**: 사건 제안이 월드 내용을 반영하는가, 지역이 이름으로 보이는가, 조정한 결과가 다음 턴에 어떻게 나타나는가, 세계가 폭주하지 않는가.
- **기술 수준**: 준개발자. 수치와 그래프를 보는 데 익숙하다.
- **불만(Pain)**: 사건 제안이 지역 UUID만 보고 만들어진다. 소문이 턴마다 4배로 늘어난다. 승격 소문 하나가 지역 전체의 감쇠를 끈다.
- **성공 모습**: 전쟁 사건을 승인하고 세 턴을 넘기면, 지도 위 왜곡도가 접경 지역으로 번지고, 플레이어 모드로 돌아가 그 지역 NPC에게서 달라진 이야기를 듣는다.
- **관계**: 기존 GameMaster 기능은 이 역할 안에서 그대로 살아 있다. "모드"라는 말은 P-Player 화면에서 드나든다는 뜻이다.
- **행적 관리 (변경 2026-09-29)**: 플레이어의 행적이 어떤 NPC의 판단으로 어디까지 퍼졌는지 보고, 과한 것은 취소한다.

## P-Viewer — 포트폴리오 관람자

- **역할**: 저장소를 열어 프로젝트가 무엇인지 파악하고, 가능하면 데모를 띄워 몇 분 플레이해 본다. 채용 담당자, 동료 개발자, 커뮤니티 독자가 여기에 든다.
- **목표**: 이 프로젝트가 무엇을 하고 왜 흥미로운지 빨리 알고, 코드가 그 목적대로 짜여 있는지 보고 싶다.
- **주요 관심**: README 첫 화면, 한 번에 뜨는가(`.env` 두 값 + `docker compose`), 원클릭 데모, 패키지 배치가 목적을 말하는가, 테스트가 있고 도는가, 무엇이 완성이고 무엇이 진행 중인가.
- **기술 수준**: 개발자. 코드를 읽는다.
- **불만(Pain)**: 지금 README는 "U1 구현 중"에 머물러 있고, Docker `service` 프로파일은 뜨지 않으며, UI 절반이 페르소나 문서에 없는 GM 콘솔이다.
- **성공 모습**: README 첫 줄에서 목적을 읽고, 5분 안에 데모 월드를 띄워 NPC와 대화하고, `locus/` 최상위 패키지 이름만 보고 구조를 짚는다.

## 내부화된 소비자 — NPC 런타임 (옛 P3)

옛 페르소나 P3 "NPC 런타임 시스템(외부 LLM NPC)"은 이번 목적에서 **Locus 안으로 들어온다.** NPC 대화(FR-C4)가 곧 그 소비자다. 외부 시스템이 붙을 수 있게 세션 지역 지식 API(`QueryResult`)는 계속 노출하지만(FR-F5, P1), 이번 사이클의 수용 기준은 내부 NPC 대화가 기준이다.

## 역할 전환 흐름

```
P-Viewer ──(clone, .env, compose up)──> 데모 월드 불러오기
                                           │
P-Builder ── 자료 업로드 / 직접 그리기 / NPC 배치 / 보강 Q&A ── 저장
                                           │
P-Player ── 세션 시작 · 배치 ── 이동 · 대화 · 행동(턴) ──┐
     ▲                                                  │
     └──────────── GM 모드 나가기 ◀── P-GM: 사건 · 소문 · 왜곡도 · 턴 · 타임라인
                                           │
P-Player ── 다른 지역으로 이동 ── 같은 사건을 다르게 듣는다 ── 저장 · 종료
```

텍스트 대안: 관람자가 데모를 띄운다 → 제작자로서 월드를 만들고 저장한다 → 플레이어로서 세션을 열고 이동·대화한다 → 필요하면 GM 모드로 개입하고 돌아온다 → 플레이어로서 다른 지역에서 같은 사건을 다르게 듣는다 → 저장하고 종료한다.
