# V6 GM 화면 — Code Review 01

**원하시는 것**: Purpose Restructure 주기에서 넘긴 일을 처리해 솔로 TRPG를 다듬는 것. 이번 주기에는 세 가지를 한다.
- 새 TRPG·판타지 디자인으로 화면을 다시 만든다.
- 결과가 틀리는 결함을 고친다.
- 시한이 있는 부채를 정리한다.

**이 리뷰가 하는 것**: 승인된 V6 코드가 승인된 설계(BR-V6-*, BLM, frontend-components, 코드 계획 § 1.1·1.3)를 지키는지 결함 위주로 확인한다.
- 범위는 `git diff a6d82d7..5404e3e -- web/src`다.
- 새 테스트가 주장대로 잡는지도 본다.
- 코드는 고치지 않았다(리뷰 전용).

**방법**: V2~V5 리뷰와 같다.
- 네 각도를 병렬로 돌렸다.
  1. 늦은 답과 상태 소유: 재현 10
  2. 쓰기·이중 실행·오류: 재현 13
  3. 배치·접근성·문구·FR-D8: vitest 재현과 headless Chrome 측정
  4. 테스트의 힘: 돌연변이 65개, 순서 섞기, 옛 테스트 이전 대조
- 재현물은 세션 스크래치의 `v6review/{state,writes,ui,tests}/`에만 두었다. 각자 작업 사본(git worktree)을 따로 만들어 쓰고 지웠다. 저장소는 바뀌지 않았다.
- 이 세션이 상위 후보의 코드 자리를 다시 읽어 확인했다.
  - `api/routers/gm.py:180`의 지지도 저장은 `enrich=False`라 `statement_ko`가 없다.
  - `locus/play/event/seeds.py:31-40`은 씨앗의 진행 여부를 끝나지 않은 사건에서 읽는다. 그런데 `AFTER.resolve`에는 `seeds`가 없다.
  - `ui/Dialog.tsx:72-77`은 닫히는 순간에만 여는 버튼을 본다.
  - `ko.ts` `timeline.set_distortion`은 `{degree}`를 날것으로 넣는다.
  - `api/schemas.py:305`의 이름표는 원문 언어에서 비어 온다.
- 판정: **C** = 재현했거나 코드로 기제가 확정됨. **P** = 기제는 실재하지만 직접 돌리지 못한 조건에 달림.
- 두 각도 이상이 같은 것을 찾은 경우는 하나로 합쳤다.
- 심각도는 화면을 쓰는 사람이 겪는 결과로 매겼다. 테스트의 빈틈은 그 빈틈이 덮는 결함의 무게로 매겼다.

## 4. 괜찮은 것 (네 각도가 확인)

- **`key={sessionId}` 경계**: 탭·띠·"새로"·오류 줄·초안·접힘·일괄이 새로 시작한다. 옛 세션의 늦은 답은 `useResource`가 끊고 `useOwn`이 키로 거른다. 같은 월드로 옮기면 월드·이름표·목록을 다시 읽지 않는다.
- **`AFTER`**: BLM § 3과 줄마다 같다(빈칸 #3·#33 제외). 실패한 쓰기는 BLM § 6이 정한 것만 다시 읽는다.
- **`conflictKind`**: 저장소 전체 호출부 넷을 확인했다. 플레이 `act`는 서버가 `session_closed`·`turn_running`·`gm_busy`만 내므로 새 갈래가 플레이 화면에서 일어나지 않는다. 코드 없는 옛 서버 동작은 그대로다.
- **대화상자 쓰기**: 끝내기와 무효화는 성공할 때만 닫히고, 거절은 대화상자 안에 보인다. 쓰는 동안 취소와 Esc가 막힌다.
- **실패가 성공처럼 보이지 않는다**: 슬라이더는 되돌아가고, 사건 폼은 실패하면 설명을 남긴다.
- **일괄**: 멈춤 규칙, 갈래별 수, 언마운트 뒤 보내지 않음이 맞다.
- **표기와 접근성 기본**: 탭 tablist와 화살표, 모든 컨트롤의 라벨, 바쁜 버튼의 모양, 새 문구의 문체 규칙, 원문 enum 없음, 범례 문장을 확인했다.
- **안정성**: 기본 순서에서 전체 613개가 통과하고, GM 파일 103개는 세 번 이어 돌려도 통과한다.
