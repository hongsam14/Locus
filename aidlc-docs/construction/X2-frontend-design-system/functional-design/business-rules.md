# X2 Frontend Design System — Business Rules

## 디자인 시스템 (BR-X2-1..6)
- **BR-X2-1** Tailwind를 도입하고 모든 시각 스타일은 디자인 토큰(색·간격·타이포·라운드·그림자)에서 파생한다. 임의의 하드코드 색/치수 지양(FR-UX1.1/1.2).
- **BR-X2-2** 팔레트는 **종이+잉크 모노**(Q2=C): 크림 배경, 잉크 블랙 테두리/텍스트, 저채도 하이라이트. 채도 높은 다색 포인트 미사용.
- **BR-X2-3** "Doodly"는 **은은하게**(Q3=A): 미세 비대칭 라운드 + 하드 오프셋 그림자 + 손그림 밑줄. 과도한 hand-drawn SVG·손그림 아이콘 남발 금지.
- **BR-X2-4** 제목/헤더는 손글씨 디스플레이 폰트, 본문은 산세리프(Q1=A). 디스플레이 폰트는 **한글 지원** 손글씨체를 로컬 번들(외부 CDN 없음).
- **BR-X2-5** 단일 라이트 테마만 지원(다크 모드 없음, FR-UX1.4).
- **BR-X2-6** 공용 프리미티브(`Button/Panel/Card/Badge/Toast/Modal` + 보조 Field/Range)를 `web/src/ui/`에 두고 기존 컴포넌트가 재사용(Q4=A). `Toast/Modal`은 스타일·컴포넌트만 제공(사용 로직은 X3).

## 계약/동작 보존 (BR-X2-7..9)
- **BR-X2-7** 기존 컴포넌트 구조·상태·이벤트 핸들러·API 호출을 유지하고 스타일만 교체한다(FR-UX1.5). 순수 프레젠테이션 변경.
- **BR-X2-8** 모든 상호작용 요소의 `data-testid`를 보존(프리미티브가 그대로 전달). 기존 vitest 계약 GREEN 유지.
- **BR-X2-9** 로컬라이제이션(X1/X3)과 독립 — 텍스트 값은 변경하지 않고 표현만 스타일링(라벨 한국어화는 X3 i18n).

## 접근성/보안 (BR-X2-10..12)
- **BR-X2-10** 잉크/종이 대비는 본문 텍스트 WCAG AA(4.5:1) 이상 유지(BR-X2-2 저채도라도 가독성 확보, NFR-UX6).
- **BR-X2-11** 폰트·아이콘·자산은 저장소에 번들, 외부 네트워크 호출 없음(SEC-B: 정적 서빙에 보안 헤더 친화 / SEC-D: 의존성 공식 레지스트리·락파일 유지, Docker `latest` 지양).
- **BR-X2-12** 레이아웃은 데스크톱 우선(Q5=A). 패널은 가로 스크롤을 유발하지 않도록 wrap/overflow 처리(최소 반응형).
